# Compaction / Spill 默认装配开发计划

状态：历史计划，已完成修复与组合验收。正式宿主的 Skill 和归档读取入口由 [基础工具与 Skills 计划](TOOLS-AND-SKILLS-PLAN.zh-CN.md)更新；本文中的 `skill` / `spill_read` 描述保留历史语境。

本轮审计修复的范围、实际测试和未验证项见[修复记录](COMPACTION-SPILL-REPAIR.zh-CN.md)；本地验收不替代真实供应商及生产环境验收。

## 1. 已确认方向

- 正式 Web 宿主默认启用 `compaction` 和 `spill`，达到阈值才处理；普通短任务不增加摘要模型调用或结果落盘。
- Skills 默认关闭。发行版可以包含 Skills，用户显式启用并重启后才扫描技能根、装配服务和注册 `skill` 工具。
- 三者都是独立可选组件。直接嵌入 Runtime 的宿主自行装配；`HostBuilder::new()` 不隐式创建磁盘存储，也不强制依赖具体压缩实现。
- 内核的校验、权限、取消、预算和结果上限始终生效。关闭组件只是回到明确的超限/截断行为，不关闭这些保障。
- 本次只实现这两项能力及默认装配调整，不扩展为 Session 数据库、长期 Memory、人工审批、MCP、多 Agent 或崩溃恢复项目。

## 2. 首次实施的基线与缺口（历史记录）

| 当前代码 | 可复用部分 | 缺口 |
|---|---|---|
| `api::ContextTransform` | 修改模型消息投影，不改正式 Transcript | 只收到消息，缺少本 Run 的只读限额及工具定义/选项的请求开销；不能只按消息长度判断完整请求是否装得下 |
| `runtime::Execution::projection` | 串行处理并校验工具消息配对 | 共用默认 5 秒 `hook_timeout`，不足以合理容纳一次模型摘要；不能靠整体放宽所有策略/选择器超时解决 |
| `RunContext.model` | 辅助调用统一计费、限次、取消和审计 | 摘要必须走此入口，且摘要请求自身也必须满足请求上限 |
| `api::ResultTransform` | 在最终结果限额处理之前归档并替换展示内容 | 缺少归档后端、按权限分页读取及清理实现 |
| `ToolResult` / `UiToolResult` | 已有 `artifact`、`original_bytes`、`truncated` | 原文定位符必须是受控引用；不能把本机路径当作浏览器链接 |
| `apps/server` 能力管理 | 编译可用性、部署默认、用户选择及重启生效 | 已加入 compaction/spill，并将 Skills 新环境默认改为关闭 |

两项限制仍明确保留：启动前就超过输入上限的历史不会自动被接纳；压缩不解除步数、任务时间、模型调用数、审计容量或检查点容量限制。首版不承诺无限运行或恢复任意大历史。

## 3. 最小架构方案

### 3.1 包与职责

| 位置 | 本次职责 |
|---|---|
| 新增 `packages/compaction` | 压力判断、完整消息组划分、摘要策略、按 Run 隔离的有界摘要缓存；普通 API 与薄 Plugin 共用实现 |
| 新增 `packages/spill` | 纯文本结果归档、本地后端、分页读取工具及保留策略；不建设通用存储中心 |
| `packages/api` / `packages/runtime` | 仅补必要的只读预算信息和上下文处理截止时间；继续拥有最终校验和执行时序 |
| `apps/server` | 组件装配、私有存储目录、部署配置、授权的用户读取接口 |
| `apps/web` | 能力状态、启停与重启提示、归档结果预览/分页查看及失败反馈 |

组件不导入 Runtime 私有类型，Runtime 不依赖这两个具体组件。复用现有注册机制，不新增插件框架或第二套模型执行循环。

### 3.2 公共契约调整的上限

现有扩展点能承载策略，但不能可靠推导每个 Run 的实际限制。实现前先记录 ADR，落实以下最小补充：

1. 提供本 Run 的只读资源限额，以及上下文投影可用的请求字节预算。包括输出结果上限，供 spill 根据实际 Run 限额工作。
2. 为上下文处理提供独立的有界截止时间，受任务截止时间和取消令牌共同约束；保留其他 hook 的原有限制。
3. 当前契约按“工具筛选 → 来源收集 → 上下文投影”执行，只预留本轮已选工具、模型选项与消息封装成本。工具选择基于已结算正式历史，每轮一次，错误恢复不重新选择；以[上下文管理](CONTEXT-MANAGEMENT.zh-CN.md)和 ADR-054 为准。
4. 所有投影仍经过消息配对校验，最终完整 `ModelRequest` 仍由网关执行原有硬限制。工具定义等不可压缩部分已经超限时明确失败。

这些信息只有执行器能按真实 Run 可靠生成，需求也适用于检索、内容投影和输出归档，不把摘要算法、文件后端或组件开关放入 Core。优先扩展现有上下文契约，不增加任意请求改写 Hook。

新增公共 Rust 字段/方法须逐项检查结构体字面量、trait 实现和插件版本兼容性；确实破坏兼容时更新 API 版本及迁移说明，不能称为无影响。HTTP/Tauri 任务协议和 UI 流协议原则上不变。

## 4. Compaction 行为

### 4.1 触发与保留

- 首版基于当前已有的规范化请求**字节预算**，不把字节估算伪称为模型精确 token 数。模型窗口/精确 tokenizer 自动发现不在本次范围；宿主可按所用模型设置更保守的请求上限。
- 初始策略：完整规范化请求的保守字节估计达到 80% 时尝试压缩，目标回落到 60% 以内。最近两组是优先保留量，必要时可减少到一个完整组；若必须保留的内容已经超过 60%，成功结果仍须严格低于 80% 且确实缩小。否则明确失败。首版不为这些技术参数增加用户设置页。
- 保留系统约束、最新用户请求及新增纠正、最近必要的完整工具轮次。最新请求之后的较早已结算工具轮次也可摘要，不能把整个单次任务都划为保护区。
- Assistant 工具调用及其对应结果作为完整组处理，不制造孤立调用或结果。保留的消息及私有 Provider 回传数据不改写；被移除的组不留下失配的私有回传片段。
- 图片、资源引用和非文本内容不剪碎；不能安全摘要的内容保留并计入预算。必须保留的内容本身超限时明确失败。
- 摘要标记为历史参考数据，不提升为系统指令。只改模型输入投影，正式 Transcript、检查点事实和 UI 历史不被摘要覆盖。

### 4.2 摘要调用与状态

- 使用当前 Run 已固定的模型配置，通过 `RunContext.model` 调用；禁用摘要请求的工具，不输出摘要模型的隐藏推理字段。
- 摘要调用计入同一任务的调用数、时间和报告 token 用量。输入要分成符合网关限制的完整组，单次触发的摘要工作量也有上限，不能递归无界压缩。
- 按 Run 和已摘要前缀保存有界缓存；相同前缀复用摘要，有新历史才增量处理，避免每轮重做。缓存不能跨 Run 共享用户内容。
- 缓存失效只影响性能，不成为执行事实来源。取消、结束、宿主关闭后释放状态；不依赖可能丢失的观察事件作为唯一清理机制。
- 摘要失败、超时、取消或产物校验失败时不发布新摘要，不重跑已经完成的工具，不开启无限重试。沿现有扩展失败语义停止当前 Run，返回可定位原因。
- 未安装/关闭 compaction 时保持现有请求限额语义；不暗中改为截断用户要求。其他上下文插件原有的超限校验也不被取消。

## 5. Spill 行为

### 5.1 保存、替换与读取

- 首版归档普通 UTF-8 纯文本工具结果，成功与已知业务错误都可处理；不修改 `call_id`、执行状态或错误含义。
- 结构化 JSON、图片和已有 artifact 的结果保持现有语义，不自动序列化成文本归档，不剪碎媒体，也不覆盖工具已有的产物引用。
- 初始触发值取 32 KiB 与本 Run 结果上限一半中的较小值。替换结果使用至多 4 KiB 的首尾预览，再按实际限额收紧；预算包含标记、定位符及元数据。
- 原文完整保存并提交成功后，才发布预览和 `ArtifactRef`。预览说明原始大小、已省略范围以及读取方式，保留原始长度和截断标记。
- 注册只读 `spill_read` 工具，使用不透明 ID 和有界分页参数；从可信 Run 上下文校验归属，拒绝跨 Run、任意路径、目录穿越及不存在的引用。读取仍经过统一工具选择、权限和取消机制。
- 读取结果自身有界，并避免再次被 spill 递归归档。摘要保留仍有用的归档引用，使模型在压缩后可以继续取回细节。
- 如果宿主限制了工具集合，只有当前 Run 确实允许读取原文时才发布可取回的 spill 结果；不能绕过 `allowed_tools` 偷加读取工具。读取能力不可用时保留原结果，交由现有 Core 限额规则处理，并明确实际行为。

### 5.2 存储与失败

- 默认后端位于宿主私有状态目录，使用每个 Run 隔离的命名空间和原子写入；不写入代码工作区，不向 UI、模型或日志暴露本机绝对路径。
- 存储目录由宿主创建并设置平台适用的私有访问权限。开发启动器的隔离状态目录同时覆盖 spill，保证验收不读写真实用户数据。
- 单条大小、每 Run 总量、全局占用及保留时间均有有限默认值，在实现阶段确定为组件常量并文档化；首版只允许可信宿主覆盖，不做通用容量管理页面。
- 活动 Run 的文件不被清理；结束后按保留时间和配额清理。读取与清理互斥，过期引用返回明确错误；启动时回收无活动拥有者的过期文件和未提交临时文件。
- 磁盘不可写、配额不足或原子提交失败时不发布假引用。遵循当前 `ResultTransform` 失败即停止的语义，保留已知工具执行状态，不能重做原工具。
- 默认开启意味着大工具输出可能暂存在本机，能力说明明确这一点。未安装/关闭 spill 后不创建新归档，回到现有有标记截断/富结果超限失败行为。
- 原文分页查看由宿主鉴权接口提供，沿用当前单一可信权限域。浏览器只显示文本，不执行 HTML，不直接打开 `spill:` 或本机路径；首版不增加附件上传或文件管理器。

## 6. 默认装配、配置与迁移

目标默认配置：

```toml
[capabilities.compaction]
enabled = true
user_configurable = true

[capabilities.spill]
enabled = true
user_configurable = true

[capabilities.skills]
enabled = false
user_configurable = true
```

- Server 默认构建包含三项能力，运行时只装配启用项。Skills 不从默认编译产物中移除，避免页面启用还要求用户重新编译。
- 同步修改仓库 `agent.toml` 和缺少配置文件时的内置默认；不能只改其中一个。
- 沿用现有优先级：编译可用性 → 部署锁定 → 已保存用户选择 → 部署默认。保留用户明确保存的 Skills 开启/关闭选择；已有自定义配置中的显式值也不被迁移覆盖。
- 没有显式 Skills 配置/选择的新环境默认关闭；仅配置技能目录不代表授权启用。保留 `AGENT_SKILLS=0` 的部署锁定语义。
- 沿用 `active`、`enabled`、`restart_required` 及版本化原子保存；修改下一次启动的装配，不热改正在执行的任务。清单显示“可用但关闭”和“未包含”的区别。
- 新增可选 Cargo features，并验证不带默认 features 的最小固定模型路径。不安装 spill 不产生存储目录，不安装 compaction 不产生摘要调用。
- Skills 开启后的既有工具行为保持不变；关闭时不实例化发现服务、不扫描项目/用户技能目录、不向模型发布技能目录或工具。

所有步骤从当前工作区已有改动继续，逐项保留其他任务变更；本计划不授权提交或推送。

Spill 先于 compaction：先减少单条工具输出对后续上下文的冲击，同时为摘要中的原文引用提供可工作的读取途径。

## 8. 必要验收

以下是原计划的验收范围；本轮实际执行与未验证项以修复记录为准。

1. **全新启动**：无项目 `.env`、无既有用户状态，compaction/spill 开启、Skills 关闭；未配置模型仍能打开设置页；未达到阈值时无摘要调用、无结果文件。
2. **真实调用链**：通过真实 Runtime + Application + HTTP/Web，使用明确标记的本地模型测试端点，驱动“大结果 → spill → 分页读取 → 多轮增长 → compaction → 最终结果”。核对工具副作用次数、预算、完整消息配对和原文一致性。
3. **摘要边界**：多工具成组、新增用户纠正、多字节文本、工具定义占用、不可压缩内容、缓存复用；取消/超时/模型失败/预算耗尽不发布半成品、不重跑工具。
4. **归档边界**：原子写失败、配额不足、读取越权、非法分页、读取与清理并发及过期引用；错误工具结果状态保留，富内容不被错误转成文本。
5. **设置闭环**：页面查看/启停/保存/重启恢复；保存失败不发布配置；显式 Skills 选择不被覆盖；关着 Skills 时放入测试技能也不会扫描或暴露。
6. **可选性组合**：两项都开、仅 compaction、仅 spill、两项都关；缺少默认 features 的固定模型路径及受限工具集合都能给出真实、明确的结果。
7. **浏览器检查**：能力页默认值和重启提示准确；归档结果可打开、分页和返回；权限/过期错误可见；无原始路径泄露或 HTML 执行。
8. **供应商联调**：可用已授权测试配置时，再跑一次真实供应商的摘要与继续执行；没有配置时如实记录未验证，不用模拟结果宣称真实联调完成。

先运行受改动影响的 Rust 定向测试及现有 `npm run test:web`，必要检查通过即停。测试夹具独立于正式模型和工具注册，不能为了验收把生成大结果的测试工具加入正式默认组合。
