## 修复边界

`TaskControl::check_model_call_available()` 只做非预留检查，并发调用仍须通过原子预留。普通任务 `check()` 不增加调用次数限制，以免最后一次获准模型调用虽然成功却不能完成任务。检查失败不会创造未开始的模型尝试；此前实际失败仍留在审计内。

适配器对同一网络块中的已解码文本、推理、工具参数、私有回传数据和用量按序输出，再输出一次错误。部分输出不能自动重试或拼接成另一次回答。工具已经执行后发生的模型重试只重发失败的模型请求，不重放工具。

压缩仅改变模型可见投影。工具调用及其配对结果保持整组，原始 Transcript 不变；摘要调用仍受共享预算、取消和总期限约束。摘要用量计入任务账目，不混作主对话输入量估算。窗口未知时保留字节限制；已知窗口时的 token 估算不是精确 tokenizer 测量。

Metadata 中 `request: null` 是明确未保留正文的标记，`partial_text` 同样为 `null`；旧记录缺失 `request` 字段仍可读取。Full 保留完整模型请求、有界部分输出证据与原容量限制。检查点的 intent、局部结果和终态仍需要确认，失败仍阻止后续执行。

## 固定长任务成本

探针文件：`packages/runtime/tests/long_task_cost.rs`。

每种配置执行完全相同的任务：初始提示词 32 KiB，64 次工具执行，每次结果 4 KiB，最后一次模型返回最终答案，共 65 次模型调用。单请求字节上限 512 KiB、审计预算 64 MiB，四种配置的 Transcript、最终答案、模型调用次数与工具执行次数相同。

成本测量分开记录：审计集合的复制/序列化每项重复五次取平均；每次模型调用额外克隆一次它收到的历史作为受控探针；检查点 Sink 额外克隆并序列化每个完整快照。Sink 同步等待，但不保留全部历史版本，也不写磁盘。

### 测量限制与本轮决策

这是一轮固定顺序的调试构建测量。任务墙钟时间包括探针、调度和宿主负载，Metadata 开启检查点的这次样本反而更慢，不能据此声称整体加速或比较两种模式的生产吞吐。审计的后置复制/序列化探针不包含在任务墙钟计时内；各列不是可直接相加的完整 Runtime CPU 分解。

历史及检查点复制列是对实际数据形状的额外受控操作，不是对所有内部复制点的完整插桩。未测量精确堆分配、峰值 RSS、磁盘写入、fsync 或真实 LLM 网络时间。字节体积和操作次数比单次时间值更适合本轮判断。

该样本中检查点序列化成本高于复制探针，后续如确有性能需求，应先在优化构建与实际持久化 Sink 下重复测量、定位瓶颈。本轮仅完成两种审计模式和成本证据，不调整检查点内部结构，不取消同步确认，不引入增量或异步旁路。
