# 基础工具与 Skills 接入开发计划

状态：已实施。日期：2026-09-22。

本计划记录本轮确认并完成的工具方向。实施保留了工作区内其他任务的改动。

## 1. 已确认方向

- 正式 Agent 固定提供 `read / shell / edit / write` 四个基础工具，普通产品配置不提供删除、禁用或替换这些工具的入口。固定的是工具身份和职责，允许修复实现问题。
- `grep / find / ls` 是三个可选补充工具，默认关闭，可按需启用。不另建“只读模式”或工具预设体系。
- 四个基础工具的参数、执行语义、输出和错误反馈以本地 Pi 实现为参照，用 Rust 落实，不自行换成另一套编辑协议。
- 新增独立 `packages/tools`，作为正式 Agent 的必备依赖。独立包不等于可选插件，不把每个工具拆成一个包。
- 后续工具实现公共 `api::Tool` 后，通过已有工具注册或 Plugin 机制追加。基础工具名保留，重名注册失败，不能覆盖基础实现。
- Skills 保持独立、可选，沿用当前默认关闭的设置。启用后发布技能摘要和文件位置；正文、参考资料由 `read` 读取，脚本通过已授权的 `shell` 执行，退役模型侧的 `skill` 工具。
- Runtime 保持唯一执行循环。基础工具的强制装配由正式 Agent 构造入口负责；底层 Runtime 的独立嵌入能力、辅助模型调用和内部禁用工具的规划调用不被取消。

## 3. 包与装配边界

| 位置 | 计划职责 |
|---|---|
| `packages/api` | 复用通用工具、上下文、结果和扩展契约 |
| 新增 `packages/tools` | 七个工具实现、基础工具集合、必要的路径/输出/进程辅助代码 |
| `packages/runtime` | 继续负责选择、校验、授权、执行、取消和结算 |
| `packages/skills` | 复用技能发现、解析、校验、重名规则，补齐可读取位置和目录生成 |
| `apps/server` | 固定装配四工具、追加可选/扩展工具、确定工作目录和执行权限、组合 Skill 目录 |
| `apps/web` | 显示基础工具状态，配置三个可选工具，使用真实结果和错误反馈 |

`tools` 的项目内生产依赖以 `api` 为边界，不依赖 Runtime 私有类型、Server 或 UI。优先普通构造函数返回工具实现，使用现有 `HostBuilder.tool(...)` 装配；仅在确有统一生命周期需求时增加薄 Plugin 入口。

基础工具使用统一工厂创建，正式 Server 无条件装配四个。宿主可以提供工作目录、执行后端和限额，但不能借普通设置替换工具身份。Server 的 `--no-default-features` 固定模型路径同样包含四工具；底层 Runtime 单独使用时仍由嵌入方组合。

扩展工具与基础工具共用同一注册表、执行链和权限检查。沿用已有重名拒绝行为，不建设第二套工具中心、动态加载器或新的 Hook 框架。

原则上不修改 Core 或公共任务请求协议。发现现有接口确实无法承载必要行为时，先记录跨业务缺口、兼容性影响和 ADR，再实施最小调整。

## 4. 基础工具行为

参数名称优先与当前 Pi 一致；描述和错误信息要明确、可供模型纠正，不暴露宿主密钥或内部配置。

| 工具 | 参数基线 | 首版行为 |
|---|---|---|
| `read` | `path`、可选 `offset / limit` | 文本按行分页，`offset` 从 1 开始；支持 Pi 基线中的常见图片并返回现有媒体内容块；明确已读范围、截断和继续读取方式 |
| `shell` | `command`、可选 `timeout`（秒） | 在任务固定工作目录启动宿主解析的 shell；工具描述明示 PowerShell/Bash/POSIX sh 语法；回传 stdout/stderr、退出结果和必要进度；处理非零退出、超时、取消及子进程清理 |
| `edit` | `path`、`edits: [{ oldText, newText }]` | 同一文件多处替换，全部基于原始内容匹配；复用 Pi 的精确优先及有限规范化匹配思路；拒绝空匹配、歧义、重叠和找不到原文的修改 |
| `write` | `path / content` | 创建或完整覆盖文件，按需创建父目录；写入提交成功后才报告成功 |

- `edit` 先完成全部匹配和冲突检查，再一次性提交；任一项失败不留下部分编辑。保留未修改内容、换行和编码标记的正确性，返回可读 diff。
- `read` 保持文本分页和媒体边界，不把超限图片编码截断成坏数据；不支持的格式给出明确反馈。读取完整 Skill 时，若分段返回，指引模型继续读取至完成。
- `shell` 的有效执行时间取任务截止时间、宿主工具上限和显式参数中的最严格值。Pi 的“未传 timeout 时无默认超时”不能取消现有 Runtime 的限额；宿主需要为实际编译/脚本任务设置合适的上限，避免沿用当前 30 秒默认值却让模型误以为可运行更久。
- 大输出使用有界采集和明确截断，不能无限累积 stdout/stderr。完整输出保存及后续读取与现有 spill 协调，避免各自维护互不兼容的归档。
- `edit / write / shell` 使用现有副作用授权和独占执行声明；只读查询可有界并行。Runtime 的独占声明只约束同一 Run，工具实现还需保护并发任务对同一文件的写入，防止本 Agent 产生交错提交。
- 路径、工作目录和允许访问范围由可信宿主确定。任务不能通过修改全局进程 cwd 影响其他任务，前端普通任务 JSON 不携带任意权限覆盖。

### Windows 基线

四个名称保持 `read / shell / edit / write`，本阶段不追加第五个默认命令工具。Windows 的 `shell` 优先使用 `pwsh.exe`，否则使用系统 Windows PowerShell；Linux/Unix 优先使用 `bash`，否则使用 `sh`。Windows 默认不依赖 Git Bash；路径转换、Unicode、空格、子进程终止必须验证。

宿主启动时自动选择系统解释器；Windows 标准安装使用自带 PowerShell，无须安装 Git Bash。若系统解释器均缺失，当前实现会返回明确启动错误，尚未提供依赖安装页面；不会静默删掉 `shell`，也不会把一种后端的命令语法伪装成另一种。`AGENT_SHELL_PATH` 是部署覆盖，旧部署的 `AGENT_BASH_PATH` 仅作兼容且新配置优先；测试使用 `SHELL_PATH` 覆盖。

## 5. 三个可选工具与配置

- `grep` 搜索文件内容，`find` 按文件路径/模式查找，`ls` 列出目录；参数、忽略规则、输出范围和截断反馈参考 Pi 对应实现。
- 三个工具默认编译进正式发行版但不注册，启用后才进入模型工具列表。不额外增加三套编译 feature，也不允许配置写入任意未安装工具名。
- 复用现有能力配置和持久化机制，每个可选工具一个开关。建议使用 `capabilities.grep / find / ls`，初始 `enabled = false`、`user_configurable = true`。
- 配置优先级、原子保存、修订冲突和重启生效规则沿用已有实现。固定四工具以状态展示，不提供开关；三个可选工具可独立选择。
- 保存失败不发布新状态；重启后模型看到的工具集合必须与页面当前生效状态一致。工具配置不注册成模型可调用的管理工具。
- 检索依赖由实现或宿主可靠提供；不能假设开发机 PATH 中存在 `rg/fd` 就认为发行版可用。若使用外部程序，要提供依赖检查和交付方案。

## 6. Skills 迁移

1. 保留项目/用户技能根、校验、重名优先级和已保存的启停选择；只在启用后发现目录。
2. 本地技能记录补齐真实可读取的 `SKILL.md` 位置。目录只发布名称、简介和位置，并说明“匹配任务先读完整指南，相对引用以技能目录为基准”。
3. 利用现有上下文组合接口加入一份有界目录，明确与 compaction 的顺序，避免每轮重复追加。Skill 名称和描述视为不可信内容并正确转义。
4. 目录只列出当前宿主允许读取的技能；通用 `read` 能访问宿主批准的技能文件及资源，写权限不因能读技能而扩大。Skill 内容不改变工具权限或覆盖系统/用户指令。
5. `read` 负责正文和资源，`shell` 负责经过现有权限检查的脚本调用；移除正式装配中的 `skill` 工具及其调用指引，删除被替代的工具消费代码和测试。
6. `disable-model-invocation` 迁移为目录中的自动推荐控制；文件访问由文件权限决定。与当前专用工具入口的拒绝语义不同，须在 ADR 和迁移说明中明确，不能声称原权限语义完全不变。
7. 禁用 Skills 时不扫描、不发布目录；通用文件工具仍可工作。启用 Skills 不增加工具数量。

当前没有远程 Skill Provider 实现，不为假想来源构建统一资源平台。已有 Registry/Provider 接口按实际使用保留，取消对模型的重复读取入口。用户手动选择技能或斜杠命令可后续通过应用直接加载正文，本阶段不扩展整套技能管理界面。

## 7. 与 Spill 的协调结果

原有 `SpillPlugin` 同时安装归档变换和 `spill_read`；只删除注册会造成归档结果无法取回，把私有存储路径直接交给模型也会改变访问边界。

落实方式：正式宿主用 `read` 读取受控归档引用，Spill 继续负责存储、配额、任务归属和清理，从正式默认集合中移除 `spill_read`。由宿主连接两个组件，`tools` 不直接依赖具体 `spill` 实现。

已落实以下具体契约：

- `read` 如何区分普通文件与现有 `spill:` 引用，以及分页单位；普通文件保持 Pi 的按行参数，不能把字节偏移伪装成行号。
- 归档读取必须使用可信 `run_id` 检查归属，保留跨 Run 拒绝、取消、有界读取和过期反馈，不暴露私有磁盘路径。
- 同步修改归档提示、读取能力判断和防递归归档逻辑；不能仅检查名为 `read` 的工具存在，就推断它支持归档读取。
- 模型侧读取与浏览器鉴权读取保持同一存储事实；现有浏览器接口和隔离语义保持完整。
- 若保留 `spill_read` 作为组件独立使用的适配器，必须与正式四工具装配明确区分，不在正式宿主重复注册。

独立组件保留 `spill_read` 兼容入口；正式 Server 使用 `through_core_read()`，不注册第五个工具。集成测试覆盖归档、`read` 分页、跨 Run 拒绝、压缩和不重放副作用。

不新增并行的 AgentBuilder 产品框架。优先在现有正式宿主中集中一次装配，并由公共工具工厂支持其他接入方复用。

## 9. 必要验收

- [ ] **默认集合**：全新隔离配置下，普通 Agent 首轮和后续轮次均获得四个基础工具；没有 `add / skill`，三个检索工具默认缺席。辅助摘要模型的禁用工具请求单独验证，不强行加入四工具。
- [ ] **真实文件闭环**：通过 Runtime 驱动 `read → edit → read` 和 `write → read`，检查真实文件内容；多编辑失败不部分落盘，重复匹配/重叠明确报错，图片和分页结果可供模型使用。
- [ ] **真实命令闭环**：验证工作目录、输出、非零退出、长输出续读、超时、取消和子进程回收；Windows 验证真实 PowerShell，Linux/Unix 验证 Bash 或 POSIX sh，不用另一种后端语法模拟通过。
- [ ] **扩展能力**：宿主追加一个测试工具并经同一循环调用；与基础工具重名时构建失败；不把测试工具加入正式默认组合。
- [ ] **可选工具闭环**：三个开关的默认、独立启用、保存、重启恢复和执行行为一致；验证保存失败及部署锁定反馈，不穷举无价值的组合测试。
- [ ] **Skill 闭环**：启用后模型先看到摘要，用 `read` 获取完整指南和相对资源，再调用已有工具完成任务；目录不会随轮次重复膨胀；关闭后不扫描技能根。
- [ ] **Spill 协调**：采用第 7 节建议后，保持大输出可取回、跨 Run 拒绝、过期反馈和防递归处理；默认仍只有四工具。关闭 Spill 的路径也能正确报告输出截断。
- [ ] **正式 Web**：无 `.env`、无既有用户状态时可打开设置并完成配置；工具可用性、加载/失败、执行输出和返回路径真实；运行必要浏览器检查。
- [ ] **无可选组件**：Server 不带默认 features 的固定模型路径仍能使用四工具；底层 Runtime 原有独立使用测试保持通过。

优先新增必要的行为测试，执行受影响的 Rust 定向测试、`cargo check -p server`、`cargo check -p server --no-default-features`；页面和配置发生变化时运行当前已有的 `npm run test:web`。`cargo test -p tools` 在新包创建后才成为有效命令。必要检查通过即停，不为提交重复运行。

集成测试优先使用明确标记的本地模型端点驱动真实 Runtime、文件和进程。交付分别标明编译、测试、浏览器流程、真实供应商和各平台的验证情况；不把本地模拟模型称为真实供应商联调。
