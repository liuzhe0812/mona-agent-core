## 2026-09-22：变换器资源收尾

`ContextTransform`、`ResultTransform` 增加有默认空实现的 `finish(run_id)`。Runtime 在工具结算和停止接纳输入后直接等待收尾，再提交终态检查点和发布最终报告；不依赖可能丢失的 `EventObserver`。每项收尾受 `hook_timeout` 独立约束，任务取消后仍调用；失败或超时会记录到报告，其他收尾继续执行，不重跑工具。执行器只负责时序，Compaction 释放摘要缓存，Spill 释放活动归档保护并清理过期文件。

这是跨组件的资源所有权需求：观察器无法保证终态送达，只有执行器知道工具已经结算。新增 trait 方法均提供默认实现，旧实现无需新增方法，传输协议保持不变；不增加通用 Hook 框架。

## 2026-09-23：ADR-050 边界验收与修正

重试的等待和预算仍由唯一模型网关负责。等待前增加调用/用量预算、取消、总期限及审计容量检查，等待后再次检查；不为未开始的重试创建虚假调用或审计。`TaskControl` 增加非预留的可用性检查，原子预留仍是最终关口；普通任务检查不因最后一次调用已经获准而阻止其正常完成。这是所有模型调用共用的执行约束，不在 Provider 内复制策略。

Provider 保留同一网络数据块内先前内容、用量和随后错误的顺序，并单调维护部分输出事实；Runtime 仍只允许无部分输出的临时失败重试。Compaction 可在没有新增可压缩组时尝试缩短已有摘要，但 Runtime 仍只给一次恢复机会，且只重发严格变小的请求。摘要算法没有进入 Runtime。

精简审计明确输出 `request: null`，不保存部分模型正文；完整模式保留原证据和容量限制。固定长任务已分别测量审计、历史复制探针和完整检查点复制/序列化；可靠提交继续同步确认，检查点结构、UI stream v2 和 checkpoint v1 均不变，不据单次调试构建测量引入增量检查点或异步提交。具体数据、测试与限制见[复核报告](EXECUTION-OPTIMIZATION-REVIEW-2026-09-23.zh-CN.md)。

## 2026-09-23：ADR-051 宿主拥有持久会话

本地会话是正式宿主的用户数据，不是 Runtime 的强制依赖。复用公共 CheckpointSink 的确认边界，由 `apps/server/sessions` 保存线性会话、持久请求身份和最新完整检查点；文件按工作空间隔离，一个工作空间只有一个写宿主。UI 从安全分页投影展示历史，而不是把可淘汰的 RunSnapshot 当权威会话。

现有公共 StartRequest 只有新 prompt，无法可信地续接历史。为所有会话型宿主增加 Rust-only `AgentApplication::start_task_with_history`，仍以当前配置决定权限、系统指令、模型与预算；不扩充不可信 HTTP/Tauri 输入面，不修改 Core、stream v2 或 checkpoint v1。恢复标识中断并保守结算未知工具，只在用户明确发送下一轮时新建 Run，不自动重做业务动作。

选择同文件两行 JSONL 的原子完整快照，而不是直接迁入 Pi 的分支树或 DSH 的事件存储框架。代价是检查点 I/O 随历史增长；容量有界且保存必须确认。本轮不引入增量检查点、后台异步旁路、分布式数据库或自动崩溃执行恢复。数据未加密，部署权限与备份属于宿主，详见[本地会话设计](LOCAL-SESSIONS.zh-CN.md)。

## 2026-09-23：ADR-052 上下文来源与有界工作集

现有串行 `ContextTransform` 无法同时表达真实用户轮次、受保护的来源内容及其预留成本，因此增加默认空实现的 `sources` 和小型 `ContextBlock`，API_VERSION 升至 7。执行器统一控制收集/预算/插入时序；具体规则、Skills、Memory 与文件 I/O 不进入 Core。主请求占用锚点以路由/配置/消息指纹限定复用，辅助调用仍共享账单但不污染窗口判断。

Compaction 只导出可校验摘要状态，不拥有会话路径。宿主以格式 2 同文件保存完整档案、工作前缀映射和最新完整检查点，保持同步确认，不采用增量检查点或异步旁路。新 Run 读取较小工作集；档案仍受有限文件容量保护。Spill 继续按 Run 保存，宿主只为属于同一会话的已确认结构化引用解析原拥有者。

项目规则属于可关闭的编码宿主能力，默认装配。首次进入有新规则的目录或发现规则改变时，副作用调用先返回未派发的拒绝，让下一模型轮次重新判断；最终权限关口保持不变。相关兼容性、明确限制和验证见[上下文管理](CONTEXT-MANAGEMENT.zh-CN.md)。

## ADR-053 三部分架构与执行契约收敛

项目按最小执行底座、可复用 Agent 扩展能力、Web 产品划分，不设置“编程 Agent”架构层。Demo 阶段不维护旧接口、旧配置和旧存储格式兼容；被替代的实现直接删除。

执行所有权统一由 `RunHandle::wait_owned` 处理：丢弃未完成的 execute Future 取消对应 Run；start 句柄和普通 wait 仅观察，不因断线取消。Engine、模型包装与会话包装共用该实现。

工具动态策略不能在整批执行前缓存，否则前序工具和慢检查点会使决定失效。保留静态预检，将 ToolPolicy 移到每次 intent 确认后、实际派发前；拒绝和异常保存为未执行结果，不撤销既有动作。规则算法仍在扩展，Core 不读规则文件。

删除 Tools 的 `tool-output:` 索引存储。Tools 仅保留有界临时采集并调用可注入 `OutputArchive`；Server 用薄适配器连接共享 `SpillArchive`，字符串结果与流式采集统一经过 `put_stream`、同一配额、权限和可靠发布。无归档时明确省略，不制造不可读引用；未加入 Core 存储依赖或第二套执行循环。验收见[机制复核](MINIMAL-HARNESS-REVIEW-2026-09-23.zh-CN.md#三个缺陷的修复与验证)。

## ADR-054 核心层累计历史与本轮请求预算

`max_history_bytes` 保护运行中累计历史，独立于启动接纳、模型请求和可选检查点限额。计数序列化器只计新增记录；模型回复接纳时预留每个工具的最小结算记录，实际派发前预留允许结果的序列化上界。调度器等待在途工具释放多余预留，空间仍不足才停止新派发，不以取消已启动工具或删除执行事实换取容量。超过容量的模型回复不接纳、不派发其工具，调用费用照常计入。

工具选择先于来源收集和投影，基于已结算正式历史每轮执行一次；不做反复选择／压缩求解。已选声明贯穿计量、主请求、检查点、工具执行与一次溢出恢复，来源成本只计一次。扩展层拥有具体选择／压缩算法，核心层只负责时序和约束。只调整当前契约，不增加兼容支路、新包、数据库或第二套循环。

## ADR-055 会话、规则与 Skills 的扩展层归位

会话文件存储、工作集恢复、归档归属和确认收尾迁入 `sessions`；规则发现与派发检查迁入 `instructions`。两包的生产依赖均不包含 Runtime 实现、Application 或传输框架。共享消息合法性校验移至 api，核心执行与会话恢复使用同一实现，不维护兼容导出。

Application 的可选 sessions 适配只连接会话接纳和已有任务注册表；Server 保留环境配置、HTTP 鉴权及安全展示。规则通过 HistorySource 注入可信档案，不绑定某种会话实现；Skills 根选择以配置工作空间为准，环境读取留在产品层。仅支持当前会话格式，删除旧格式读取、迁移和原 Server 实现。

可靠保存、取消与未知副作用语义保留；不引入新执行循环、增量检查点或通用存储平台。
