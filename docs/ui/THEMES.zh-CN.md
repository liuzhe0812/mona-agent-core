# Web UI 主题与皮肤

## 用户入口与边界

在“设置 → 外观”选择皮肤。石墨、海盐蓝、松林绿、鸢尾紫、暖砂和蔷薇各提供浅/深两套配色；明暗模式可选浅色、深色或跟随系统。保留顶部明暗切换按钮，手动操作后保存为明确的浅/深模式，不再跟随系统。

默认是石墨、浅色、15px 普通消息正文、标准圆角。字号选项为 14/15/16/18px；圆角为标准、柔和、利落，只作用于气泡、聊天输入器、详情和主要面板。标准值按输入器/气泡/面板/详情为 22/12/12/8px；柔和为 28/16/16/12px；利落为 12/8/8/8px。主输入器的蓝色发送角色和轻投影属于组件合同，不新增任意可导入样式。普通按钮、表单输入和导航仍遵循设计系统，不被皮肤改变。代码、标题、工具详情和普通控件保留各自字号，不是整页缩放。选择即时保存和应用，右侧样式预览不创建会话或发送任务。

本功能是 Web UI 的主题系统，不是 Agent 插件。没有增加 Rust 包、Runtime 行为、公共任务协议、模型工具或宿主管理接口；切换外观不会触碰聊天订阅、任务状态、会话内容或草稿。背景图上传、跨设备同步、任意 CSS/脚本插件和主题市场不在首版范围内。

## 实现位置

| 文件 | 职责 |
| --- | --- |
| `apps/web/theme.mjs` | 预设、严格校验、受控样式应用、保存/恢复、系统模式和跨标签同步 |
| `apps/web/design-system.css` | 主题可覆盖的语义角色与不可随皮肤漂移的组件/布局合同 |
| `apps/web/appearance.mjs` | 外观设置控件、预览、导入导出、恢复默认和错误反馈 |
| `apps/web/appearance.css` | 设置页面与预览的响应式样式 |
| `apps/web/index.html` | 外观入口；head 提前加载主题模块 |
| `apps/web/styles.css` | 正式页面只通过设计系统的语义色彩和有限圆角、字号变量消费主题 |
| `apps/web/theme.test.mjs`、`apps/web/test/themes-e2e.mjs` | 纯逻辑测试及真实浏览器受控联调 |

主题模块同时从 head 和设置模块引用，ES Module 实例复用，不创建两份主题管理器。head 使用 `blocking="render"` 请求支持该属性的浏览器在主题应用前等待；未支持该属性的浏览器仍有基础样式回退，不宣称所有引擎绝对无首帧闪色。当前浏览器验收使用 Chromium/Edge。

## 保存与失败语义

存储键为 `mona.web.appearance.v1`，值仅包含 `version`、`skin`、`mode`、`fontSize`、`shape`、`custom`。不保存模型凭据或会话。作用域是当前浏览器、当前站点；不同端口或浏览器不会自动继承。同站点标签页通过原生 `storage` 事件同步，并重新读取当前持久值而不是直接应用过时事件载荷。

保存遵循“先写入存储，再发布新外观”。浏览器存储不可用或写满时，保留之前的选项和实际外观并显示失败。读取到错误格式、未知版本或丢失的皮肤时，使用默认外观并显示提示，不自动覆盖原数据；重新选择或恢复默认可以主动修复。存储不可读不会阻止基础页面及 Agent 连接。

“恢复默认”恢复内置默认外观，但保留自定义槽位。导入仅有一个槽位，新导入替换旧导入。尚未提供多自定义皮肤库或删除入口；可通过再次导入替换，或保留但不选用。

## 皮肤文件约定

通过“导出当前皮肤”得到可编辑的样本，再从“导入皮肤”选择 JSON。文件上限 32 KiB（按 UTF-8 字节计），导出只包含配色，不包含浏览器偏好、聊天记录或凭据。

顶层必须且只能包含以下字段：

| 字段 | 要求 |
| --- | --- |
| `format` | 固定为 `mona-theme` |
| `version` | 整数 `1` |
| `name` | 去除两端空白后 1–32 个 UTF-16 代码单元；拒绝控制字符和双向文本控制符 |
| `light` | 完整浅色配色对象 |
| `dark` | 完整深色配色对象 |

每个配色对象必须且只能包含：`bg`、`panel`、`text`、`muted`、`line`、`soft`、`accent`、`sidebar`、`selected`、`danger`、`success`、`switch-on`、`focus`、`inverse`、`activity-shimmer`。每个值只接受六位十六进制 `#RRGGBB`，加载时规范成小写。不接受任意 CSS、URL、图片、脚本或未知字段；名称通过文本节点呈现，不解析 HTML。

校验文字/次级文字在主要背景上的对比度至少 4.5，成功/错误文字在页面和面板上的对比度至少 4.5，强调按钮的文字对比度至少 4.5，焦点颜色对主要背景至少 3。这是有限的导入保护，不替代对完整交互状态、透明度和辅助技术的无障碍验收。

增加内置配色时，向 `theme.mjs` 的 `SKINS` 添加一条同时提供浅/深配色的数据并验证既有测试；修改内置代码需要交付新的前端资源。用户导入符合约定的 JSON 不需要重新编译前端或 Rust 后端。扩展新的视觉能力时，应显式扩展受控主题契约及测试，而不是开放任意脚本。

## 验证

`npm run test:web` 运行现有 Web 单元测试、设计门禁及主题逻辑测试；`npm run check:web:design` 防止页面绕过语义 Token；`npm run test:web:design` 验证主题与统一组件尺寸的真实计算结果。`npm run test:web:themes` 使用真实浏览器和受控 HTTP/SSE 端点验证设置、持久化、失败反馈、窄屏以及任务执行中的换肤。浏览器脚本需要 Node 22+ 和 Chromium/Edge，可通过 `BROWSER_BIN` 指定；流程、测试范围和输出路径见 [浏览器验收](../../apps/web/test/README.md)。没有真实供应商调用，也未据此声明生产或 Tauri 全面验收。
