# Mona Agent Web UI 设计系统

## 1. 权威与范围

本文件是 `apps/web/` **正式运行界面**的视觉与交互正本。正式入口是 `index.html`，包括主工作区、任务侧栏、聊天与执行过程、搜索、设置、模型与连接弹窗、主题和窄屏形态。它只定义 UI，不改变 Agent Runtime、公共协议、模型、工具、权限或会话语义。

Mona Web UI 设计系统由本仓库独立维护。极简、语义 Token、紧凑控件、三档控件尺寸、可见层圆角、浅深双态、无装饰阴影、键盘与动效纪律，均属于 Mona 的正式设计决策；不依赖外部设计规范或快照才能成立。

冲突时按以下顺序处理：

1. 本文件与 [组件合同](./COMPONENTS.zh-CN.md)。
2. `apps/web/design-system.css` 中的生产 Token 和共享基础样式。
3. 当前正式页面的真实浏览器行为与验收证据。

`preview.html` 与 `apps/web/src/` 是早期离线预览/自定义元素实验，不属于正式 Runtime 页面，也不作为设计验收依据；其定位记录在[生产界面台账](./DESIGN-INVENTORY.zh-CN.md)。

## 2. 设计原则

- **工具优先。** 内容、任务状态和操作是主角，装饰不得与其争夺注意力。
- **紧凑而不拥挤。** 低信息噪声不等于放大所有元素；按钮、输入、列表和设置项保持工具型密度，通过删减无关信息而不是巨型留白获得平静感。
- **每个表面一个概念。** 多阶段内容使用分组、折叠或独立页面，不堆叠多层卡片。
- **平面层级。** 主结构依赖背景差异、排版和 1px 分隔线；普通页面、卡片和按钮不使用装饰阴影。
- **颜色有语义。** 组件只消费语义颜色；焦点、成功、失败等有明确角色，不能把品牌色随意扩散到普通操作。
- **可见层决定形状。** 圆角分配给具体边框、表面或图元，不按 HTML 标签猜测。
- **状态稳定。** hover、pressed、focus、disabled、loading 不改变控件尺寸或文字位置。
- **真实能力。** 未安装能力、连接失败和空数据必须如实显示，不切换到假数据。

## 3. Token 架构

```text
apps/web/design-system.css
  Mona Foundation → Semantic → Component/Layout
                    ↓
apps/web/theme.mjs 覆盖语义配色和受控外观变量
                    ↓
styles.css / sessions.css / appearance.css
```

### 3.1 Foundation

| 类别 | 生产约定 |
| --- | --- |
| 字体 | UI 使用 Inter + 系统无衬线回退；代码使用系统等宽栈 |
| UI 字号 | 10、11、12、13、14、15、16px |
| 标题字号 | 18、20、24px；正式工作界面不使用更大的展示标题 |
| 字重 | 400 常规、500 默认强调、600 限量强调；普通 chrome 不使用 700 |
| 间距 | 4、6、8、10、12、14、16、20、24、32、40、48px，优先使用 Token |
| 控件高度 | 32px（紧凑）、36px（默认）、40px（宽松输入） |
| 图标按钮 | 28、32、36px 三档；默认 32px |
| 边框 | 1px；不新增 2px 以上普通边框 |
| 动效 | 80/150/200/250ms 四档及进入/退出曲线，均通过 Token 消费 |

### 3.2 圆角

| 可见层 | 圆角 |
| --- | ---: |
| 无框表面 | 0 |
| 数据/消息尾部等已登记微形状 | 2px |
| 键盘键帽、极小内容标记 | 4px |
| 内层控件、菜单行、textarea、列表 hover | 8px |
| 卡片、面板、Dialog、标准聊天气泡/输入器 | 12px |
| 按钮、单行输入、Select、标签、开关轨道 | 9999px |

外观设置的“柔和/利落”只允许通过 `--skin-composer-radius`、`--skin-bubble-radius`、`--skin-panel-radius`、`--skin-detail-radius` 调整聊天输入器、消息、详情和主要面板。默认标准值为 12/12/12/8px；普通按钮、表单输入和导航控件不随皮肤改变形状。

### 3.3 语义颜色

页面只能消费 `design-system.css` 暴露的 `--surface-*`、`--border-*`、`--text-*`、`--accent-*`、`--status-*`、`--focus-*` 等角色。具体皮肤通过 `theme.mjs` 提供 `bg/panel/text/muted/line/soft/accent/sidebar/selected/danger/success/focus` 等配色，再映射到同一语义层。

正式 feature CSS 禁止写死 hex、rgb、hsl；不得绕过语义层为某一套皮肤单独打补丁。浅色、深色和每个实际触及的状态必须在同一任务内完成。

## 4. 全局布局

### 4.1 主工作区

- 桌面由任务侧栏、可拖动分隔条和主工作区组成；默认侧栏 264px，可调范围 208–460px。
- 顶栏固定 48px；普通顶栏操作使用 32px 图标按钮或紧凑文字操作。
- 主内容最大阅读宽度为 900px；聊天和输入器共用该宽度，并随窗口流动收缩。
- 侧栏只承载品牌/搜索、新建任务、任务列表和设置，不显示当前协议不存在的项目树、自动化或插件市场。
- 搜索由品牌行按钮或 `Ctrl+K` 打开，不长期占用侧栏空间。
- 任务列表按用户参考图实现两个状态：平时是分组标题“任务”加折叠箭头，行内左侧任务标题、右侧相对时间（刚刚 / N分钟 / N小时 / N天，超过一个月显示日期）；悬停分组标题时右侧出现分组操作图标（刷新、新建任务），悬停任务行时时间位置换成该行的操作按钮（`⋯`），行宽不变，行只在悬停或选中时出现浅色反馈。任务行常驻图标占位：正在执行的任务在该占位里显示转圈指示（`--motion-spinner-cycle`、8 帧步进；它承载执行状态，减少动效下仍继续转动），任务结束后占位保留、指示隐藏，标题的位置与缩进不随状态变化。列表刷新复用既有行节点，不重建节点导致转圈动画不断从头开始。时间位置仍保留相对时间；失败、中断等已结束的异常状态改为占用时间位置并使用 `--status-danger`。
- 任务行右侧只有**一个**位置：相对时间与行内操作占用同一个盒子、右边缘对齐，静止时显示时间，悬停或键盘聚焦时原地换成操作，两者互斥、不同时出现，标题与行宽都不因此变化（标题最右边界止于该盒子左侧）。行内操作是置顶（`aria-pressed` 反映状态）与 `⋯`（打开该任务的菜单）。
- `⋯` 与右键打开同一个任务菜单，每一项都带线条图标：重命名任务、置顶聊天/取消置顶、归档/取消归档、标记为未读/标记为已读、删除任务；删除放在最后并使用 `--status-danger`。归档把任务移出当前列表，归档视图里菜单项变为「取消归档」，因此归档可恢复。宿主尚未提供的能力（例如生成分享链接）不出现，也不在浏览器里伪造状态。未读任务在行的图标占位里显示一个圆点（执行中的转圈优先），打开该任务即清除未读标记。
- 分组标题的悬停操作是 `⋯`（列表操作菜单：刷新列表、显示/隐藏已归档任务）与新建任务；`⋯` 菜单是查看和恢复已归档任务的入口，因此归档不是单向操作。

### 4.2 设置

- 设置侧栏桌面宽度 232px；页面内容上限 1040px，桌面内边距 32px。
- 页面标题 20px，说明 13px；导航项高 36px。
- Agent 组件与 Agent 工具使用独立设置页。普通设置项最小基线 72px，桌面基线验收不超过约 84px；行内只保留名称、必要说明、开关和确实存在的重启提示，不显示当前状态或管理策略等冗余标签。
- 供应商侧栏 240px，头部以 72px 为基线，供应商标识 36px；模型行最小 52px，包含上下文等第二行元信息时可自然增长到约 68px。
- 设置页是管理工具，不使用营销页式的大标题、48px 图标或 50px 以上空白来表达层级。

### 4.3 窄屏

- `≤680px` 时任务侧栏变为抽屉，分隔条隐藏；工作区去除外框圆角。
- 设置导航置顶并可换行，内容改为单列；供应商列表和详情上下排列。
- 390px 和 320px 都不得出现页面级横向滚动。代码、命令和表格只在自己的内容容器中滚动。
- 响应式只改变布局和可用宽度，不更换任务语义、控件层级或消息身份。

## 5. 正式页面规则

### 5.1 新任务与建议

首页仅显示任务起点、简短说明、真实建议和输入器。建议使用 12px 容器、1px 边框和紧凑文本；不增加宣传卡、营销副标题或假能力入口。

### 5.2 聊天

- 用户消息靠右，使用主题表面和 1px 边框；右上角 2px 是已登记的消息尾部形状。
- 助手正文直接进入阅读流，不套卡片、不显示头像。
- 普通正文默认 15px / 1.6，用户可在 14/15/16/18px 中选择；标题、代码和工具详情不随该设置等比例放大。
- Markdown 只渲染受支持子集，始终创建 DOM 节点，模型内容不得通过 `innerHTML` 执行。
- 可点击链接静止状态就有下划线；代码底色只表达代码，不代替可点击信号。

### 5.3 执行过程

- 外层摘要高 32px；真实活动行高 28px，行间保持紧凑。
- 文本项独立成行；同一步骤多个工具调用折叠为一组。空模型回合不生成占位行。
- 行静止时无填充，hover 使用轻表面；失败/拒绝/取消保留可见状态。
- 行的标签是工具类别（终端 / 读取 / 搜索 / 写入），图标使用同 `.line-icon` 契约的 15px 线条图标；工具命令或参数作为该行的等宽摘要跟在标签之后，行展开后不再重复显示该摘要。
- 详情面板使用 8px 默认内层圆角、1px 边框、紧凑内边距；面板只承载命令与输出：一行 `$ 命令` 加有界输出正文，不重复工具名、不出现“结果/成功”一类标签和页脚，失败由行状态与输出正文本身表达。命令和结果有界滚动。
- 协议没有独立的思考事件：Runtime 只把模型返回的推理保留在消息里供供应商续接，不进入事件流或快照。因此过程区不生成“思考”行，也不把中间文本伪装成推理。
- 运行文字流光是功能性进度例外；减少动效时变为稳定文字，不得扩散为装饰动画。

### 5.4 输入器

输入器与聊天共享阅读宽度，标准圆角 12px；内部 textarea 无第二层边框。聚焦时由外框显示 `--focus-ring` 和 soft ring，不能同时给 textarea 再画一圈。模型选择和发送动作保持 32px 控件密度。

### 5.5 弹窗和搜索

- 普通表单 Dialog 最大约 460px，供应商表单可到 560px；视口两侧至少 16px。
- 容器 12px 圆角、16px 内边距；标题 18px，输入 36px，操作按钮 36px。
- 可自由放弃的表单使用底部“取消”+ Esc +遮罩关闭，不同时放置右上角 ×。
- 搜索弹窗可以没有底部操作，通过 Esc/遮罩关闭；结果行使用 36px 高、8px 内层圆角。
- 关闭后焦点回到触发元素；保存过程中不得重复提交。

### 5.6 空态、错误和状态

空态说明发生了什么以及下一步能做什么。错误包含问题与可执行下一步，不使用只有“失败”的句子。成功反馈描述改变的对象，不重复“成功”。加载、禁用、空数据和未安装能力都必须来自真实状态。

## 6. 交互与无障碍

- Tab/Shift+Tab 保持正常顺序；只有具体组件可以在自身范围内消费键盘。
- 所有图标操作至少有随状态变化的 `aria-label`。鼠标提示使用 `data-tooltip` 与全局 `tooltip.mjs`：浅色为白底、1px 细边、12px 圆角，14px 正文与 8×12px 内边距；深色跟随主题。不使用原生 `title` 重复显示，不额外添加说明文案。
- **不使用焦点环**：可见控件不绘制 outline 或柔光环（`--focus-ring` / `--focus-ring-soft` 仅作为 theme 数据保留，未被任何可见层使用）。键盘操作依靠控件自身的 hover/active 表面与 DOM 顺序表达。
- 提交型 textarea：Enter 发送、Shift+Enter 换行；IME composition 中 Enter 不发送。设置页普通单行输入不因 Enter 自动保存。
- 内容正文、代码和结果可选择；按钮、标签、导航和状态 chrome 不作为复制内容。
- `prefers-reduced-motion` 移除非必要过渡与动画，但保留即时状态反馈。

## 7. 动效与深度

普通 hover/颜色变化使用 150ms；展开/尺寸变化使用 200ms；重型覆盖层进入可使用 250ms、退出 150ms。拖动侧栏直接跟随指针，不加缓动。禁止 `transition: all`、弹跳、视差、循环装饰和按字符打字机动画。

基础 UI 不使用投影。仅焦点 soft ring 和未来在本规范中登记的浮层例外可以出现 `box-shadow`；普通卡片、设置面板、工作区和按钮均为 `none`。

## 8. 文案

- 操作使用“动词 + 对象”，避免孤立的“确定/提交”。
- 进行中使用明确对象和省略号，例如“正在读取…”。
- 错误说明原因或可行检查项；空态指向第一个可执行动作。
- 页面内容只服务用户，不出现开发者提示、测试说明或给教师/运维人员看的内部文案。

## 9. 实现与治理

正式 CSS 分为：

- `design-system.css`：Foundation、Semantic、Component/Layout Token 和共享基础组件。
- `styles.css`：主工作区、聊天、执行过程、搜索、能力和模型设置。
- `sessions.css`：任务历史导航。
- `appearance.css`：外观设置与预览。

Feature CSS 不得新增裸颜色、任意字号、字重、圆角或硬编码动效时长。修改规范、Token 或组件合同的流程、例外与验收要求见[设计治理](./DESIGN-GOVERNANCE.zh-CN.md)；当前页面覆盖情况见[生产界面台账](./DESIGN-INVENTORY.zh-CN.md)。

必要检查：

```sh
npm run check:web:design
npm run test:web
npm run test:web:design
npm run test:web:themes
npm run test:web:sidebar
```

真实浏览器检查与截图是视觉证据，单元测试或静态门禁不能替代目检。验证范围必须如实区分受控 fixture、真实 Rust 宿主、真实供应商和 Tauri WebView。
