# Mona Web UI 设计治理

## 1. 四种事实

| 类型 | 权威来源 |
| --- | --- |
| 设计规则 | `DESIGN.zh-CN.md` 与 `COMPONENTS.zh-CN.md` |
| 生产数值 | `apps/web/design-system.css`；主题配色由 `theme.mjs` 提供 |
| 生产范围 | `DESIGN-INVENTORY.zh-CN.md` |
| 视觉事实 | 正式页面的真实浏览器截图和计算样式 |

Mona 的规范、Token、组件合同和真实浏览器证据共同构成生产真相。任何外部项目的实现都只能作为临时研究材料，不能成为仓库内的运行依赖、命名空间或设计权威。

## 2. Token 分层

1. **Foundation**：字体、字号、字重、间距、尺寸、圆角、动效。
2. **Semantic**：surface、border、text、accent、status、focus、overlay。
3. **Component/Layout**：settings/sidebar/dialog/activity 等稳定角色。
4. **Theme**：只覆盖允许换肤的语义色与受控聊天/面板外观变量。

新页面优先消费现有 Token。没有合适角色时先说明复用为什么不成立，再新增；禁止为了消除门禁把任意值伪装成无语义 Token。

## 3. 代码纪律

正式 feature CSS（`styles.css`、`sessions.css`、`appearance.css`）必须满足：

- 无裸 hex/rgb/hsl。
- 字号来自 `--ui-text-*` 或已登记的用户正文变量。
- 字重来自 400/500/600 三档 Token。
- 圆角来自已登记的 `--ui-radius-*` 或受控 `--skin-*`。
- 动效时长来自 motion Token。
- 无普通装饰阴影；focus soft ring 是已登记例外。
- 不恢复 116px 设置行、25/26px 设置标题、56×54px 页面边距等历史过大几何。
- 正式 HTML 不写内联 style。
- 正式运行时 JS 不直接写颜色、字号、圆角或组件尺寸；仅允许已登记的侧栏宽度、主题变量和浮动菜单坐标钩子，门禁按文件和语句白名单检查。
- 侧栏 208/460/264/16px 和菜单 8/4px 等必须在 JS 中以命名常量存在，并与生产 Token、组件合同和浏览器断言同步。
- Footer 已有 Cancel 的可关闭表单不再增加右上角 ×。

执行：

```sh
npm run check:web:design
```

门禁只保护可机器判断的约束；通过不等于视觉验收完成。

## 4. 变更流程

### 普通页面改动

1. 确认台账中的正式 surface 和拥有文件。
2. 复用组件合同和 Token。
3. 同时完成浅色、深色、必要状态和窄屏。
4. 运行静态门禁、相关单测和真实浏览器检查。
5. 检查截图，报告实际覆盖范围。

### 新 Token / 新组件角色

必须说明：

- 现有角色为什么无法表达。
- 它是跨页面通用还是业务局部。
- Light/Dark、focus、disabled、error 如何表现。
- 是否扩大主题导入范围。
- 是否需要静态门禁、计算样式断言或截图基线。

同一改动中更新设计规则、组件合同、生产 Token 和测试；不能先写页面裸值，之后再承诺治理。

### 例外

已登记例外目前包括：用户正文 14/15/16/18px、消息尾部 2px、运行文字流光、focus soft ring、受控皮肤圆角。新增例外必须写清角色、范围和不能扩散到哪些组件；“看起来更好”不是充分理由。

## 5. 验证层级

| 层级 | 命令/证据 | 证明什么 |
| --- | --- | --- |
| 静态 | `npm run check:web:design` | 未引入明确禁止的设计值和结构 |
| 逻辑 | `npm run test:web` | 主题、客户端、会话和设计门禁逻辑 |
| 正式浏览器设计 | `npm run test:web:design` | 计算尺寸、正式设置数据、Dialog、聊天、浅深与窄屏 |
| 主题 | `npm run test:web:themes` | 皮肤、持久化、导入、执行中换肤 |
| 导航 | `npm run test:web:sidebar` | 侧栏、拖动、搜索、键盘和抽屉 |
| 真宿主会话 | `node apps/web/test/sessions-e2e.mjs` | Rust 宿主、持久会话、真实工具和重启恢复 |

受控 fixture 不代表真实供应商；Chromium/Edge 不代表 Tauri WebView；自动检查不代表完整无障碍认证。交付说明必须区分。

## 6. 截图与审查

视觉改动至少查看：

- 桌面浅色主界面。
- 桌面深色相关界面。
- 受影响的设置/弹窗/空态/错误态。
- 390px；涉及紧凑布局时再看 320px。
- 长文本、长模型名或长工具参数。

截图输出到 `.tmp-verify/`，不作为生产资源提交。截图显示问题时以真实布局为准，不能因 DOM 测试通过而忽略。

## 7. 与并行开发的关系

设计迁移不得改变 Agent 执行、公共协议或业务配置语义。保留用户及其他任务的未提交改动；不要借 UI 规范化重写无关 JS。页面功能变化需要独立需求和验证，不能隐藏在“设计整理”中。

## 8. 维护

- 新增正式 surface：先登记台账，再实现。
- 删除/替换正式 surface：同步台账和测试入口。
- 参考外部实现时，只提炼适合 Mona 的原则并形成独立决策；不复制外部品牌目录、命名空间或规范快照进入生产设计系统。
- 修改设计系统后运行全套必要检查，避免只验证本地单一页面。
