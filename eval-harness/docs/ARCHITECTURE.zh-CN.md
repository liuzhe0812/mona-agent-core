# Eval Harness 架构与运行边界

本工程是被测 Agent 之外的独立系统，不属于 Mona 核心层、扩展层或产品层中的新一层。其职责是执行预先定义的测评、观察证据、自动判定并保存结果。

## 组件

```text
Web / CLI
    │ 相同 Manager 接口
    ▼
Catalog ── 任务、评分规则、可用 Adapter、模型配置
    │
    ▼
Manager ── 请求去重、任务队列、有界并发、取消、报告提交
    ├─ Trial 独立 workspace / state / home
    ├─ Adapter ── 自检 / Mona HTTP / 通用 JSON Lines 进程
    │      └─ 被测 Agent ── 本地模型网关 ── 实际模型端点
    ├─ Graders ── 根据输出、实际文件、工具证据判定
    └─ Store ── SQLite 报告 / 有界日志 / 单题证据
```

`harness/` 不导入任何 Mona 包；`adapters/mona.py` 是唯一知道 Mona HTTP 路由和 UI Snapshot 结构的地方。Web 不直接启动 Agent 或访问被测目录。生产 Python 仅使用标准库，前端是原生 ES Module 与 CSS。

设计参考 Harbor 的“任务指令／执行环境／验收器”分工，以及 Inspect AI 的运行记录、配置与样本证据组织。不直接集成这两个框架，也不宣称兼容其任务格式。

## 一次运行

1. 校验配置、授权、能力声明、任务集、并发和预算；同一 `request_id` 与相同配置返回既有记录，不启动第二次。
2. 保存 queued 报告后启动协调器。一个数据目录同时只跑一套评测，套件内部并发至多 4 个 trial。
3. 每题每次重复都创建新的工作目录、状态目录和 HOME。只把 prompt、公开 fixture 及运行参数交给 Adapter；不传评分条件或答案。
4. 执行 turn；明确设置 `restart_before` 时重启该 trial 的自有宿主并保留指定状态。其他 trial 不共享状态。
5. 接收真实结果后，由评分器读取工作文件、消息与工具终态。没有必需证据时返回 inconclusive，而不是猜测成功。
6. 清理拥有的进程与连接，保存单题完整证据并同步磁盘；最后发布完成结果。报告引用证据的 SHA-256，下载时复核。

测评顺序和 fixture 由版本化任务确定；真正模型输出可能变化，所以报告保留重复次数而不自动挑最好一次。默认没有自动任务重试。

## 被测 Agent 与模型网关

网关不实现 Agent、不修改请求内容、不增加上下文、不执行工具、不改模型参数。它是本次环境中可观察的模型入口：记录实际请求次数、请求大小／哈希、HTTP 状态、首次内容时间、供应商报告用量。

- 每个 trial 独立令牌、计数器、端点和生命周期，不能借另一个 trial 的预算。
- Chat Completions、Responses、Messages 的真实请求保持原字节；鉴权换成实际端点的凭据，必要协议版本头原样转发。禁止重定向，避免凭据被转移。
- 费用未知：没有绑定供应商计价表，`cost=null`。
- Token 是事后观测约束，不是严格预付费配额。达到上限不再准入后续请求；单次返回超限会导致本题失败。上个完成请求没有用量时，无法确定剩余额度，下一次请求直接拒绝。
- 无代理流量的真实模型通用进程任务标为证据不足。外部 Agent 绕过网关进行的请求不能被此模型观察器发现；可信 Adapter 必须遵守接入契约。
- 自检不调用模型；受控夹具只用于明确的小型工程测试，不用于给真实模型评分。

真实端点的计量正确性需通过对应协议的集成测试验证；不要把受控端点测试称为供应商联调。

## 进程所有权和取消

控制器用自有 supervisor 启动子进程；控制管道关闭表示失去所有者，应终止这个进程树。Windows 使用 Job Object，Unix 使用独立进程组。取消也关闭本题在途模型连接，Mona 先发送自己的 Run 取消请求再清理宿主。

这些机制是生命周期控制，不是对抗恶意程序的安全边界。没有文件系统访问控制、容器网络隔离或磁盘配额。可信进程仍可能执行有副作用的工具，因而非自检 Adapter 需要操作者显式授权。

总期限包括初始化、目标运行和重启；清理有单独的有界等待。资源清理失败不允许保留 passed 结论。重启后将 queued/running/cancelling 转为 interrupted，不自动重新执行，也不自动收费。

## 结果、指标和比较

报告记录运行身份、模型／协议、任务与评分器指纹、测评源码哈希、Adapter 版本信息、Mona 二进制哈希、系统环境及明确限制。通用 Adapter 的 `revision` 由配置提供，不伪造其 Git SHA。

必需检查均通过才 passed；失败、跳过、环境异常、超时、取消、中断、证据不足分别计数。成功率以所有计划 trial 为分母，不通过减少分母掩盖没有执行的题。

数据指标包括端到端与初始化／执行／评分／清理耗时、模型调用、已报告 token、工作区和状态文件体积。`peak_rss_bytes`、`disk_io_bytes` 当前为 null；文件体积不称为磁盘吞吐或泄漏证明。时延包含本地代理与报告记录成本，不能直接当成裸 Agent 性能。

比较保持原任务哈希对应，只展示观察差异；任务集、运行性质、预算、重复与并发不同会明确警告。不自动输出统计显著性或安全总评分。

## 持久化与产品边界

`Store` 使用本机 SQLite WAL、FULL 同步和系统文件锁；锁冲突拒绝启动，数据损坏报错，不重置为“空历史”。展示日志每次运行最多保留 2000 条，API 每页 200 条；截断单独标记，不影响持久化单题证据。

`server/app.py` 仅 loopback，固定静态资源白名单，同源校验与请求令牌。Web 中没有任意命令配置或密钥输入接口；Adapter 启动命令由可信本地配置文件提供，凭据从环境变量加载。

工作台重开后报告仍可查看。已保存输入、原始产物和业务内容属于私有测评数据；精确已知凭据脱敏不等于完整数据脱敏。文件保留直到操作者删除记录；没有后台自动淘汰。
