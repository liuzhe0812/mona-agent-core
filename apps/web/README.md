# Mona Agent Web UI

这是 Mona Agent Core 的正式通用 Web UI。它使用与 HTTP Bridge / Tauri Bridge 相同的流式工作项协议，但本身不实现 Agent Runtime。

视觉规范见 [UI 设计规范](../../docs/ui/DESIGN.zh-CN.md)。`design-system.css` 管理 Mona Token，主页面保持原生 ES Module。正文由 `content-renderer.mjs` 将 Markdown Token 转为受控 DOM：使用固定自托管的 markdown-it、KaTeX、Highlight.js 和 Mermaid，不再维护简化的 Markdown/数学/流程图语法解析器。原始 HTML 作为文本，公式关闭信任能力，图表在无同源权限和网络权限的专用 iframe 中计算，输出清理后以图片显示。

代码块支持语言高亮、复制、换行、下载和长代码展开；表格支持复制 Markdown、安全 UTF-8 CSV 导出、放大及宽表横向阅读。单张图片显示缩略图，连续纯图片段落组成画廊，可在大图中前后切换；加载失败可原位重试，外部 HTTPS 图片仍由用户确认后加载。Mermaid 完成后显示图形，双击图形或使用放大操作查看大图。文件引用、工作区图片和文件卡片绑定来源会话，通过鉴权接口读取或打开右侧预览，不能由模型文本扩大本机文件访问权限。

流式输出按时间窗口合并，稳定 Token 块保留 DOM 与展开状态，代码高亮和图表计算延迟到完成后。较长 Markdown 在 Worker 中解析；超限、排版失败保留完整原文并可重试。长历史使用分页加载、浏览器原生离屏布局优化和按需工具/图表渲染，不将它描述成无限容量的虚拟会话数据库。

工具区按真实事件显示状态，日志增量更新不替换整个面板；`coding.diff` 展示真实合并/左右差异，未知 namespaced detail 安全回退 JSON。工具富内容仍遵守既有有界 UI Projection：远程私有地址、隐藏推理和任意 structured 不直接透传。当前协议没有独立思考事件，因此不把中间助手文本冒充思考过程。

## 一键连接真实 Runtime

在仓库根目录直接运行：

```sh
npm run dev:web
```

启动器会同时启动：

- Rust `server`：真实模型模式，默认 `127.0.0.1:8787`。
- Web UI Server：默认 `127.0.0.1:4173`。
- 浏览器中的 UI 会自动使用 HTTP/SSE Bridge 连接，不需要手工复制 Bridge Token。

无需 `.env` 或 `npm install`。最终用户分别通过“设置 → Agent 组件”和“设置 → Agent 工具”管理可选装配项，通过“模型设置”添加供应商；未配置模型时不会退回假模型。完整说明见 [本地开发文档](../../docs/DEVELOPMENT.zh-CN.md)。

## 模型协议

供应商编辑可选择 Chat Completions、OpenAI Responses、Anthropic Messages，支持自定义 API Base 和只写 API Key。修改端点或协议需重填或清除密钥；不自动尝试其他协议。原生协议可在折叠的推理设置中填写白名单 JSON，服务端验证后保存。

模型编辑中的折叠区可保存工具、图片、采样、停止序列的三态能力及输出上限；未知不推测，发现模型不覆盖这些设置。接口支持图片不等于每个模型具备视觉能力，本轮未增加附件上传产品入口。跨协议私有历史不兼容时明确提示新会话，不静默改写记录。

## 记忆管理与历史检索

“设置 → 记忆”提供个人/当前工作区的精选长期条目、来源、容量及增删改；真实 Markdown 保存在宿主，不在浏览器持久化。来源内容稳定注入，新请求可见后续纠正或删除。Agent 默认只读，主动写入需在 Agent 工具页授权并重启；用户在管理页的直接编辑不等于给模型授权。

同页可按关键词搜索历史、读取有界原文页和相邻消息、打开实际会话。管理查看属于当前本机用户权限域；模型工具只拿到宿主限定的普通/项目范围。搜索不调用额外模型，不把整个数据库加入上下文；无匹配、冲突、取消和保存失败如实显示。实现和边界见[上下文与三类记忆](../../docs/architecture/CONTEXT-MEMORY.zh-CN.md)。

## 模型窗口与项目上下文

模型列表中的“上下文窗口”可设置具体供应商/模型的 token 容量，新增模型时也可填写；未知保持空值。保存及发现模型不会丢失已有容量，改变只影响新任务。窗口估算、输出预留和字节硬限制由后端处理，界面不自己计算或伪造容量。

“设置 → Agent 组件 → 项目规则”控制工作空间 AGENTS.md/CLAUDE.md 自动加载，内置默认开启，切换后下次启动生效。长会话会复用已保存的工作摘要；历史页仍展示原始消息。同会话旧 Spill 文件经归属验证后可读取，过期或删除会明确提示。实现与限制见[上下文管理](../../docs/CONTEXT-MANAGEMENT.zh-CN.md)。

## 设计系统

正式 Web UI 已统一接入 Mona 设计系统：普通按钮/输入默认 36px，紧凑操作 32px；设置侧栏 232px、桌面内容边距 32px、页面标题 20px；组件与工具设置行按内容紧凑呈现，供应商头部和模型列表使用统一行高。容器默认 12px，内层控件 8px，普通动作与单行输入使用胶囊形；基础页面不使用装饰阴影。

实现分层：`design-system.css` 维护基础、语义和组件 Token，`styles.css`、`sessions.css`、`appearance.css` 只描述各自 surface。正式范围和历史预览边界见[生产界面台账](../../docs/ui/DESIGN-INVENTORY.zh-CN.md)，具体尺寸见[组件合同](../../docs/ui/COMPONENTS.zh-CN.md)，变更流程见[设计治理](../../docs/ui/DESIGN-GOVERNANCE.zh-CN.md)。

```sh
npm run check:web:design
npm run test:web
npm run test:web:design
```

静态门禁禁止正式 feature CSS 新增裸颜色、任意字号/字重/圆角、硬编码动效时长和普通投影，也限制运行时 JS 只能使用已登记的侧栏宽度、主题变量和菜单坐标钩子；真实浏览器检查覆盖主工作区、三类设置、Dialog、浅深色、聊天和 390/320px。

## 主题与皮肤

入口为“设置 → 外观”。提供石墨、海盐蓝、松林绿、鸢尾紫、暖砂、蔷薇六套皮肤，每套都有浅色和深色配色，并可跟随系统。消息普通正文可选 14/15/16/18px，面板圆角可选标准、柔和、利落；标准档为 22px 主输入器、12px 容器/气泡和 8px 详情内层。

选择即保存并生效。外观只保存在当前浏览器、当前站点的 `localStorage`，同站点标签页同步；刷新和浏览器重启可恢复。保存失败保留旧外观并显示错误，读取到损坏数据时回退默认但不静默覆盖旧数据。换肤只更新样式，不清空草稿、不重建聊天节点、不重连或重跑任务。

可导出当前皮肤的浅/深色配色，也可导入最多 32 KiB 的 Mona JSON 皮肤。自定义皮肤仅保留一个槽位，再次导入会替换；恢复默认保留已导入皮肤。导入校验字段、版本、颜色和基本对比度，不接受脚本、任意 CSS 或外部图片。预览区明确是样式样本，不触发 Agent。

实现仅位于 `apps/web/`，不使用 Rust Plugin，也不新增宿主接口。首版不包含背景图上传、跨设备同步或主题市场。文件格式、职责边界和验证方式见[主题系统](../../docs/ui/THEMES.zh-CN.md)。

## 新任务与输入器

新任务只展示居中的 Mona LOGO、标题和输入器，无说明或建议卡。输入器采用 22px 圆角、细边框与轻投影；底部操作行参考 DSH InputBar：左侧是 28px `+`、文件权限和仅在启用时出现的“计划”状态，右侧是模型选择和 34px 蓝色圆形发送按钮。第一条消息开始后同一个输入器停靠底部；项目归属仍可显示在输入器上方，空上下文不占位。

普通执行是默认状态，不常驻显示“执行模式”选择器；启用 Planner 后，从左下 `+` 菜单进入计划模式，宿主确认后才显示“计划”状态按钮，点击该按钮退出计划模式。计划模式实际写入会话状态，只允许 Planner 与宿主选定的只读工具，方案形成后仍须明确继续执行；刷新和重启按会话恢复。

## 本地会话

会话正文的“查找”（`Ctrl+F`）按原始文字匹配，可跨粗体、行内代码等格式定位；工具日志需要时才展开读取。界面明确标注已加载范围，可继续分页搜索更早历史并停止，不把局部结果当成全库结果。加载历史保留已有轮次和阅读锚点，切换会话可回到之前阅读的历史页；“返回最新对话”和“回到底部”区分历史页与当前滚动位置。用户长输入可展开，回答可通过图标复制其完整原文，不包含隐藏的中间过程；选择正文可引用到输入器或填入侧边对话草稿，操作本身不执行任务。

连接中断显示“任务状态待确认”，可重新读取快照与订阅，不自动再次启动任务。宿主已无实时 Run 时，持久会话回到已保存记录。历史页单次读取失败只显示该区域的重试入口，不把任务改成失败或清空已有正文。 异步读取期间用户重新滚动时，以新的阅读位置为准；工具日志自身滚动不改变整页跟随意图。关闭正文查找会取消延迟高亮，关闭并重新打开任务搜索时不会接收前一次搜索的迟到结果。

正式 HTTP 宿主默认将会话存入本机用户目录。左侧按任务列出本地会话，支持分页、重命名和删除；搜索位于 Mona 标题右侧的按钮（或 `Ctrl+K`）打开的弹窗中，由宿主按名称查询，不在侧栏常驻输入框。打开历史后继续发送，会从宿主读取可信消息上下文，不是仅在页面上拼接旧文本。新建任务不会继承其他任务历史。

侧栏顶部的 Logo 后有当前窗口访问过的任务后退/前进按钮（`Ctrl+[` / `Ctrl+]`），只在有对应历史且可切换任务时启用；任务删除后从该历史移除。侧栏展开时，收起按钮紧跟搜索按钮；收起后，同一个按钮移到会话标题左侧，`Ctrl+B` 使用同一切换逻辑。窄屏抽屉使用相同入口，关闭后焦点回到顶栏按钮。

会话顶栏沿用 ZCode 的任务标题结构：已保存会话显示工作区信息按钮、标题和 `⋯`，草稿态不显示这三项。工作区信息浮层展示宿主给出的目录、最近活动和可读取的 Git 分支，不切换项目；`⋯` 使用真实会话操作，提供置顶、重命名、归档、未读，以及当前宿主可提供的任务文件浏览、工作区路径和会话 ID 复制。只有桌面宿主声明系统打开能力时才显示右侧分体按钮；下拉按参考样式提供“资源管理器”和“终端”，选择后立即在系统独立窗口打开当前会话工作区，并记住本浏览器的选择。普通 Web 不显示该按钮。顶部单独的终端按钮与 `Ctrl+J` 仍控制内嵌 PTY 标签和右侧面板；右侧面板自身可用 `Ctrl+Alt+B` 开合。系统打开方式与内嵌 PTY 是两套明确的操作。Web 宿主没有桌面已安装编辑器发现、系统窗口控制、更新提示、任务记录/日志路径、模型调用轨迹或反馈接口，这些桌面专属入口不伪造；分享和帮助暂不显示。

左侧承担任务导航：品牌与搜索、普通新建任务、可选项目及各自任务、普通任务和设置。项目与任务分区的标题和右侧按钮共用同一横向基线；两个六点手柄可拖动交换分区上下顺序，也可聚焦后按 `Alt+↑/↓`，顺序保存在当前浏览器。点击项目手柄仍切换项目行排序，点击任务手柄打开刷新列表、已归档视图菜单；普通任务行本身不因此进入拖动模式。每组先显示五条，可按组继续展开；移除项目登记后的历史进入普通任务组。项目区可折叠，项目行排序时可拖动项目行或用方向键移动，顺序保存在当前浏览器；项目行提供操作菜单和项目内新建任务，不放文件浏览入口。全局和“任务”分组的新建操作不继承最近项目；点击项目行可在对应目录开始任务。未编译或未装配 projects 时隐藏项目入口，普通会话及文件栏照常使用。侧栏宽度可以拖动右边界调整，也可以 Tab 聚焦分隔条后用左右方向键调整，范围 208–460px，结果只保存在当前浏览器；窄屏下侧栏是抽屉，不提供侧栏宽度拖拽。

Web 宿主中，“添加项目”只输入名称，宿主在当前默认工作区下创建同名目录并登记；成功后切换到该项目，取消不创建目录。页面不要求绝对路径。`apps/desktop` 直接复用本页面，Tauri 宿主提供 `folder` 模式：弹出系统文件夹选择器，选定后登记已有目录，取消不修改项目。

任务列表平时显示标题与相对时间，任务行常驻图标占位：正在执行的任务在占位里显示持续转动的指示（减少动效下仍转动，因为它承载状态），任务结束后占位保留、标题位置不变。行右侧只有一个位置：相对时间与行内操作（置顶与 `⋯`）占同一个盒子、右边缘对齐，静止显示时间，悬停或键盘聚焦时原地互换，两者互斥且标题宽度不变。`⋯` 与右键打开同一个任务菜单，每项都带线条图标：重命名任务、置顶聊天/取消置顶、归档/取消归档、标记为未读/标记为已读、删除任务（最后一项、危险色）；置顶与归档由宿主持久化，置顶排到列表最前，归档把任务移出当前列表且可由已归档视图恢复。未读任务在图标占位里显示圆点，打开该任务即清除标记。生成分享链接这类宿主没有的能力不出现在菜单里。任务分组标题悬停显示六点手柄与新建任务；拖动手柄可交换项目和任务分区，点击手柄打开刷新列表和显示/隐藏已归档任务的菜单，因此归档可以恢复；分组折叠箭头只改变本地显示，并记在本浏览器。

刷新或重启会恢复已确认的消息与工具结果；异常中断有明确状态，不自动重跑模型或工具。尚未确认的流式片段及瞬时进度不保证保存。数据不放在浏览器 localStorage，完整设计、存储位置及安全边界见 [本地会话](../../docs/LOCAL-SESSIONS.zh-CN.md)。

## 会话过程与统计

聊天、输入器、停靠卡和统计共用阅读宽度；三栏同时打开时优先保留聊天空间，右栏按实际可用宽度缩小或转为浮层，返回宽屏后恢复用户偏好。草稿自动增高和收缩，在短屏上达到限制后仅文本区滚动。输入器底部左侧承载 `+`、文件权限和活动计划状态，右侧承载模型和发送；窄卡片按需隐藏权限文字或分行，不缩成难以操作的按钮。左右模态区域关闭后恢复可见焦点，不会把聊天留在不可交互状态。

连续工具活动形成过程组，助手说明保留在组间；运行中显示实际当前动作，结束后按已记录的读取、修改、搜索、命令数量汇总。成功且没有补充输入的轮次可收起过程，最终回答保持可读；失败、停止和有补充输入的轮次不整体隐藏。外层只显示本轮耗时或异常状态，组标题负责当前活动，不重复显示命令。组内长过程在有界区域独立滚动，打开运行组从最新活动开始，打开历史组从头开始；手动上翻后新增内容不抢走阅读位置。普通助手说明与最终回答使用相同正文字号。

输入器下方提供执行、Token、上下文三个紧凑统计入口，与输入器对齐并维持单行。点击在视口内的顶层面板查看模型/工具用时、平均首 token 时间、输出速度、缓存分项和上下文组成；窄屏仅缩短可见文本，不改变完整可访问名称。持久会话读取保存的全会话统计，不拿当前已加载的历史页充当总数。Token 是已报告用量（含辅助调用），不完整时显示下界；缓存字段缺失时命中率与分项显示未提供。上下文圆环显示最近主请求的占用比例，详情中的系统、工具、消息组成用 `~` 标记估算；无窗口容量时不显示百分比。切换会话清除旧统计，后台页停止轮询，已结束任务不持续轮询。

## 工作区与右侧工作面板

普通会话在可配置默认根下各自分配一个稳定工作目录，后续多轮和重启复用；项目会话直接使用项目目录。默认初始根是用户主目录下 `~/.mona-agent/workspaces`，可在“设置 → 工作区”修改，部署变量 `AGENT_WORKSPACE_DIR` 可覆盖并锁定。修改只影响新普通会话；已保存会话不改绑。移除项目登记、删除/归档聊天都保留用户文件。

左侧始终保留项目和任务导航。文件树作为右侧的“文件”页面按会话或项目独立打开，按需展开目录并可按文件名查找；右侧还承载文件预览、只读 Git 审查、用户交互 PTY 终端和临时侧边对话。面板默认收起，打开内容时展开；支持拖宽、全屏和至多两个独立窗格。各窗格拥有自己的标签与活动内容，可移动标签、调整比例或合并窗格；退出全屏和切换会话保留分栏。窄面板不能新建分栏，已有分栏变窄后上下排列；最后一个标签关闭时收起面板并归还焦点。布局只改变CSS位置，不重建文档或终端。当前窗口保存有界文件路径、分组、活动项、比例、源码/换行偏好与面板开关；刷新后重新鉴权，不保存正文、凭据、终端命令或旁支历史，不迁移旧布局。

文件树和预览均使用一行路径工具栏，复制/下载/换行进入文件菜单。文件搜索与浏览分别保留状态，清空搜索恢复目录展开；晚到的查询不会覆盖新结果。预览刷新失败保留旧内容并提供重试；分页复制明确只复制已加载文本。 Office 等完整文件预览在新文件读取和排版确认后才替换旧文档；失败不清空已经显示的版本。表格、图片和图表的放大视图属于原消息或文件页，关闭来源、切换来源标签或连接后会一起关闭。授权图片读取失败可在原位置重试，不重新执行任务。

文件浏览与终端输入不调用模型；旁支复用原 Agent 执行接口而不改写主会话记录。终端输出可重新连接，但输入确认未知时禁止自动重放。旁支断线也保留待确认状态，不能当作已完成再次提交。

文件预览支持代码/文本、Markdown 源码切换、栅格图片缩放、隔离的静态 HTML/SVG、浏览器 PDF/音视频以及独立沙箱中的 DOCX/XLSX/PPTX 引擎，并提供有界鉴权下载。不能安全读取的路径/版本明确拒绝，未安装格式不伪装成功。桌面为三栏，窄屏为独立浮层；不是完整 IDE、原生内嵌浏览器或 Shell 沙箱。接口、资源生命周期和权限边界见[应用层与 Web/桌面装配](../../docs/architecture/WEB.zh-CN.md)，第三方资源来源见 [vendor](vendor/README.md)。

会话存储只使用当前格式 5，包含有界宿主扩展状态及每轮统计，不读取或迁移旧格式。任务列表跳过无法读取的后台文件，不在输入器下方显示文件扫描计数；打开指定任务失败时仍给出对应错误。清理旧 Demo 数据是用户的明确操作，界面不会静默删除它。存储接口见 [Sessions](../../packages/sessions/README.md)。

## 单独使用界面

标准入口是 [index.html](index.html)。它使用原生 ES Module，因此需要通过 HTTP Server 或 Tauri WebView 加载，不能依赖 `file://` 直接双击。它包含连接设置：

- Web / 远程场景选择 HTTP Bridge。
- Tauri 宿主选择 Tauri Bridge，不需要本地 HTTP Server。
- `npm run dev:web` 会在开发环境自动完成 HTTP 连接。

## UI 模块接入

`app.mjs` 是连接、任务和会话外壳，不再直接初始化 Models、Memory、Workspace、Workbench、Side、Metrics 等具体控制器。`ui/host.mjs` 读取受鉴权的 `/api/ui`，依据 `ui/catalog.mjs` 的本地加载函数装配模块；`ui/registry.mjs` 提供有限 Slot，`ui/shell.mjs` 连接现有布局。架构参考 DSH Client Module/Slot，运行技术栈仍为原生 JS。

| 扩展点 | 贡献内容 |
|---|---|
| `settings` | `{tab, panel, activate}`；导航和页面节点归该模块 |
| `composer.actions`、`composer.mode`、`composer.dock`、`status` | HTMLElement，按注册 order/id 排列 |
| `right.pane` | `{label, icon, available, run}`，配合 `ctx.shell.pane(ctx.id)` 打开有所有者的标签 |
| `tool.view` | 按详情 key 的渲染函数，失败回退为通用 JSON |
| `presentation` | 按来源会话返回文件、资源等展示回调 |
| `composer.commands` | 命令处理函数，或 `{run, menu}`；带 menu 时贡献到 `+` 菜单 |

模块导出 `version = 1` 与 `mount(ctx)`，注册通过 `ctx.register(slot, {id, order, value})` 完成。 依赖的 `mount` 完成后才启动子模块；清单刷新加入的新模块会收到当前 connection 和 session，已就绪模块不会重复初始化。`ctx.own(dispose)` 管理自己的资源，`ctx.listen` 管理长寿命 DOM 监听，`ctx.on` 订阅 connection/session/run/busy/display/assembly 等产品事件。模块可通过 `ctx.capability(id)` 读取实际装配事实；后端执行权限仍由产品接口判定。动态列表的局部监听随其节点生命周期释放，不能每次渲染向全局目标重复注册。

新增模块时，在 `ui/catalog.mjs` 登记固定加载函数与显式依赖，并在 Server 清单中按实际支持条件列出模块 ID；不得从远程数据构造 import 地址。模块在已有 Slot 内接入不需要修改前端主流程。设置可沿用产品内的受信模板，也可由模块创建导航和内容节点；模型生成的 HTML 不能成为模块模板。UI 契约与 Core 的 PluginManifest 分开版本化。

设置节点随注册项移除；`setting` 配合受信 `claim` 模板支持同页重连，重新挂载得到新节点。异步动作可用 `ctx.guard` 包装，仍须在跨等待后检查自身会话/请求身份。`ctx.shell.draft()` 读取当前草稿，`submitText(text, sessionId)` 可明确限定发送目标；这些接口不等于执行授权。

`details` 提供归档读取和专用 Diff/Plan 渲染，即使后端不再允许新计划，旧计划也可以只读显示。`appearance` 与 `conversation-rail` 属于纯前端本地模块；后者拥有会话轮次导航的观察器、定时器和动态刻度监听，模块释放时一并清理。业务管理模块跟随当前连接装配，切换连接释放旧资源和凭据；退出展示模块不取消正在执行的任务。

### 输入框命令菜单

`+` 打开与输入框同宽的上方浮层，按“添加 / 指令”分组，显示图标、中文名称、英文命令与右侧说明。当前由 Planner 注册 `plan`、Sandbox 注册 `permission`、Models 注册 `model`；能力未实际启用时不显示，空分组不保留。自动上下文压缩已实现，但尚无手动压缩入口，因此不展示 `compact`。

`menu` 提供 `section`（`add` 或 `command`）、`label`、`description`、`icon()`、`visible`、`disabled`；后两项可为即时求值函数。`run(argumentsText)` 处理命令；可选 `menu.select()` 表达菜单动作，例如计划菜单切换状态，而 `/plan` 明确进入。模块状态变化后调用 `ctx.refreshCommands()`，刷新不调用模型；执行前重新检查可用性与注册身份。只需要斜杠调用的命令不必提供 menu。

权限和模型菜单分别打开既有选择器，打开本身不变更配置、不创建 Run。模型选择沿用当前产品的默认模型设置，只影响后续任务，不伪称仅修改当前会话。计划退出仍受宿主校验：待继续的方案不能通过普通模式切换绕过明确执行操作。菜单支持键盘导航、Escape、外部点击与会话切换关闭，不消费已有草稿。

### 计划模式

标准宿主默认直接执行，不显示常驻“执行／计划”下拉。Planner 可用时，左下 `+` 菜单出现“计划”；进入后才在操作行显示“计划”状态按钮，点击可退出。计划模式只调研、提交方案；计划辅助区或右侧“计划”标签显示状态、调整原因和完整方案，“继续修改”重新进入规划，“按此计划执行”使用确认后的同一会话发起下一轮。状态先在宿主保存，刷新或重启恢复；运行中禁止切换，旧版本操作会报冲突。

模块是否编译、期望开关和当前生效状态是不同事实。尚需重启的开关不产生假可用控件；禁用 Planner 保留历史只读显示；Planner 本身不提供沙箱或通用审批。具体后端边界见[产品 UI 架构](../../docs/architecture/WEB.zh-CN.md#ui-modules)。

验证入口为 `npm run test:web`、`npm run test:web:design` 和 `npm run test:web:extensions`。端到端测试使用隔离宿主、真实文件工具与受控模型，日志不含正式用户数据；它们不证明真实模型的规划质量。

### 沙箱模式

`ui/modules/sandbox.mjs` 向输入框底部的模式插槽注册常驻文件权限选择，文案与 DSH 对齐为“仅可查看 / 工作区内修改 / 完全权限”，标准宿主默认“工作区内修改”。该选择控制 Shell 与 write/edit 的文件副作用范围；Planner 则控制 Agent 是直接执行还是先形成方案，两者语义独立、可以同时生效。实际权限和后端状态从宿主读取，不以页面变量代替授权，也不把部分限制伪装成完整隔离。

模式先按会话 revision 保存，下一 Run 使用固定策略；切换会话、刷新和重启恢复宿主记录。执行中禁用选择，部署锁定不可修改，旧响应不覆盖新会话；停用组件需重启生效，已有受限会话不会自动变为不受限。沙箱不可用的错误保留，不自行重试或弹通用审批。验收入口为 `npm run test:web:sandbox`。

### 子 Agent

`ui/modules/subagent.mjs` 通过既有设置、右侧面板和工具详情插槽装配。“子 Agent”设置维护并发、深度、角色指令、模型身份和工具上限；保存后的期望配置与当前有效配置分别显示，重启后生效。工具权限中的“继承父任务工具上限”与明确空白名单不同：未勾选且留空表示不给任何工具，不会保存成全权限继承。角色切换保留未保存的编辑。

右侧“子 Agent”展示当前根会话的真实任务、状态、模型和本轮用量；选中后可查看最近 50 轮及每页最多 30 项的安全执行过程。补充信息只保存到子任务消息区，下次模型请求可见；继续与停止是独立操作。父任务已结束时，“交给主 Agent 继续”在主会话发起明确的新请求，不绕过总预算独立启动子 Run。停止不回滚文件，刷新或重启不自动重做工作。

面板按连接、根会话和子身份隔离，卸载时取消自身读取与轮询；浏览器关闭不取消任务。未装配扩展时仍可查看历史，但不能伪造新委派入口。产品回归入口为 `npm run test:web:subagent`。

### MCP

`ui/modules/mcp.mjs` 通过 settings 插槽管理 stdio 命令/参数/目录/环境和 Streamable HTTP URL/标头，提供启停、工具过滤、宿主只读声明及实际连接状态。null 与空工具数组分别表示全部和不提供工具；只显示宿主实际装配的工具，不在页面生成假目录。

保存使用 revision，确认落盘后更新状态；配置变更提示重启。已保存 env/header 值不回显，留空保留；清除凭据和端点变更在宿主再次校验。刷新不覆盖正在编辑的表单，切换连接或卸载清空输入凭据并取消读取。重连使用当前实际配置，不重新派发模型任务。验收入口为 `npm run test:web:mcp`。

## 与 Core 的边界

```text
Web UI
  -> JavaScript AgentClient / RunView
  -> HTTP 或 Tauri Bridge
  -> AgentApplication
  -> Agent Core
```

UI 负责渲染文本增量、工具工作项、最终状态和取消操作；Core 负责 ReAct、模型、工具、权限、取消和资源限制。关闭订阅不等于取消任务，停止按钮必须调用独立的 cancel 接口。

## 当前交付边界

- 正式通用界面通过独立的宿主会话接口打开持久历史；不在前端维护 Session 数据库，也不包含产品账号或多租户权限系统。
- 模型设置通过独立的 HTTP 管理接口工作；页面可以提交用户新输入的凭据，但已保存的模型密钥不会返回浏览器，也不会写入 `localStorage`。浏览器拿到的是本机开发 Bridge Token。
- “Agent 组件”和“Agent 工具”是两个独立设置页，只展示宿主已编译且允许用户开关的项目；固定基础项、最小必备项和部署锁定项不显示。只有变更确实等待重启时才显示“重启后启用/停用”。
- 上下文压缩和长结果归档在正式 Web 组合中默认开启，达到阈值才工作；Skills 默认关闭。Artifact Viewer 通过经过鉴权的同 Run/同会话接口分页读取文本归档；Rich Content 只显示安全 UI 投影，不把本机路径、远程私有 URL、任意 structured 数据或 HTML 执行能力暴露给页面。
- Tauri Bridge 当前只支持临时任务；会话区和模型设置页会如实提示宿主尚未接入对应管理接口，不宣称具备本地会话恢复。
- 直接部署到公网前，需要把这套模块化 UI 纳入正式前端构建与认证体系。
- 当前仓库未把 UI 发布为 npm 包；调用协议客户端位于 `packages/client/`。
