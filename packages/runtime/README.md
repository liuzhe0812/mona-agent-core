# runtime

`runtime` 提供唯一默认 ReAct 循环、模型网关、工具调度、取消、预算、事件状态和 Plugin 生命周期。它只依赖公共 `api`，不依赖 Web UI 或具体模型协议。

```rust,ignore
let mut host = runtime::HostBuilder::new()
    .model(model)
    .tool(tool)
    .build()
    .await?;
let report = host.engine().execute(api::RunRequest::new("task")).await?;
host.shutdown().await?;
```

启动时先完成消息/容量校验和实际模型的 `validate_history`，再派发执行任务。模型专属历史不兼容时，尚未运行来源、摘要、模型或工具，也不预留模型调用；Runtime 不解释端点、签名或摘要内容。独立预检成功不锁定模型配置，`start` 仍重新检查。

## 历史容量与结果结算

`max_history_bytes` 默认 8 MiB，限制本 Run 实际保留的规范 JSON 历史；它独立于初始接纳、单次请求和检查点上限，即使不安装任何扩展也生效。使用计数序列化器增量计量，不为测量额外分配整份 JSON，也不把摘要投影当成实际历史。

追加输入先检查容量，再写检查点和确认接纳。完整模型回复只有能容纳回复及所有工具配对的终止记录时才进入历史；否则终止 Run，不执行其中的工具，不把已显示的流式片段伪装成已接纳回复。模型尝试仍计入预算和审计；原有响应限制继续约束临时收集。

每项工具派发前按允许的最大结果、JSON 转义与元数据预留空间，结算后释放多余预留。空间暂时被在途工具占用时先等待其完成，必要时降低实际并行度；最终不足则停止新派发，未执行项记为 Skipped。不会为腾空间取消已启动工具、删除已确认历史、缩小工具原有结果上限或拆散调用/结果。预留是保守上界，不代表实际分配同等内存；`max_history_bytes` 也不是整个进程的内存限额。检查点失败、外部取消和超时仍按原语义停止。

模型临时故障可通过 `RunLimits.model_retry` 有限重试；默认 `max_retries = 0`。只重试尚未产生文本、推理、工具调用或私有回传内容的 `ModelTransport`、`ModelRateLimit` 和 `ModelServer`，每次实际尝试都计入调用预算与审计。等待前检查取消、总期限、调用/用量预算和审计容量，等待结束后再次检查；预算已经耗尽时不先等待，也不为未开始的尝试预留调用或创建审计。等待本身受取消和总期限约束。上下文超限不走普通重试；Runtime 仅在投影确实缩小后重发一次。

适配器主动报告的 `model_output_started` 也会阻止重试；网关只可把该事实从 false 升为 true，不能覆盖成 false。活动工作项更新与事件序列提交在同一锁范围完成，展示裁剪不会删除活动项的增量或终态。

工具参数在派发前按 JSON Schema 校验，失败结果最多包含四条字段路径和原因，总计不超过 1024 字节，不回显参数值。数值约束给出 Schema 中的具体边界，例如 `/limit: must be > 0`；嵌套位置使用 JSON Pointer，例如 `/edits/0/newText: expected string`。执行工具数量由 `MAX_TOOL_CALLS_PER_STEP` 与 Run 限额控制；UI 快照的 256 项保留量只影响展示，Runtime 单独保留活动项直到结算。

静态参数、模型可见工具和宿主授权先预检。动态 `ToolPolicy` 对每个实际候选调用只检查一次，位于 intent 确认之后、工具派发之前；因此前一个独占工具修改规则后，同批后续工具会重新判断。拒绝和检查失败记录为未执行结果，保存失败仍停止后续动作。intent 不等于工具已派发；这不是跨 Run、外部进程或文件系统的原子事务。

`execute()` 统一使用 `RunHandle::wait_owned()`：拥有者 Future 被丢弃即取消该 Run，不取消共享任务或其他 Run。`start()` 句柄和普通 `wait()` 是非拥有型观察入口，丢弃或断线不自动取消。

完整审计保持原行为；精简审计显式输出 `request: null`，也不保存失败时的部分模型正文。检查点仍是可选的完整可靠快照；模型调用前、工具派发前、结果结算和终态提交的确认屏障保持不变，未安装 Sink 时不会产生检查点复制或存储 I/O。

每轮先把已结算的正式历史交给 `ToolSelector` 收紧工具集合，再收集 `ContextBlock` 来源、压缩投影，最后在 System 消息之后插入来源。工具 Schema 只按本轮已选集合计量；`RunContext.request_tools`、请求开销、主请求和执行校验使用同一份声明。选择器不依赖尚未生成的摘要或来源，也不在重试／溢出恢复时再次执行。来源上限、取消、总期限和工具配对均由核心校验；恢复复用同一轮工具和来源，不重复计入来源成本。Runtime 不读取 AGENTS.md 或会话文件。

模型网关仅为主对话请求建立输入用量锚点：以请求配置/工具声明及逐消息 SHA-256 验证相同前缀，新增尾部近似计量；辅助摘要用量只计费、不污染锚点。锚点不额外保留正文，精简审计语义不变。见[上下文管理](../../docs/CONTEXT-MANAGEMENT.zh-CN.md)。

网关按实际模型尝试累计完整输入、输出及可用的缓存分项；输入总量和原有用量限额不改变。单调时钟记录请求耗时、成功请求首个有效片段的等待时间和有完整输出用量时的生成速度，工具派发后单独累计执行耗时。摘要等辅助调用计入任务用量与模型用时，但不更新主会话上下文锚点；统计与任务检查点一起保存，不产生额外模型调用。

必要验证：

```sh
cargo test -p runtime
```

固定长任务成本探针单独执行：

```sh
cargo test -p runtime --test long_task_cost -- --ignored --nocapture
```

探针比较相同 64 个工具回合下的完整/精简审计与检查点开关；区分审计序列化体积、历史复制探针、检查点复制和序列化成本，不把内存 Sink 结果当成磁盘持久化或生产性能。测量结果与验收范围见[五项优化复核报告](../../docs/EXECUTION-OPTIMIZATION-REVIEW-2026-09-23.zh-CN.md)。
