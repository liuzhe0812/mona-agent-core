# spill

`spill` archives large UTF-8 plain-text tool results behind an opaque `spill:` artifact reference. The `SpillResultTransform` commits the complete text before publishing the reference. Its standalone Plugin can register `spill_read`; the formal Server uses `through_core_read()` and routes the same run-scoped pages through its fixed `read` tool, so Spill does not add a fifth default model tool.

`LocalSpillStore` uses `<root>/<hex(run_id)>/<opaque-id>.txt`, commits complete files before exposing references, and enforces finite per-entry, per-run, and global quotas. Runtime awaits the result transform's `finish` on completion and cancellation, releases the Run's active-file protection, and cleans expired inactive archives. Cleanup also runs before subsequent writes and at formal-host startup; it is lazy retention, not a timer. Writer admission and cleanup share one lock so active archives are not deleted by another Run's cleanup. Cleanup failures are reported rather than treated as success. Direct transform users must call `finish` after their tools have stopped. The root directory is created only when the first entry is stored.

`spill_read` clamps each page to the Run's result cap, including serialized metadata. The formal host's `read` adapter additionally budgets its artifact descriptor and preserves its one-based cursor. UTF-8 pages never exceed the requested byte limit; invalid character-boundary offsets and limits too small for one character are explicit errors. Reads seek to the page rather than loading the entire archive.

The backend requires a dedicated storage directory for one host. Unix directories/files use verified 0700/0600 permissions. On Windows, the first access sets and verifies current-user-only ACLs for the root and any existing archive tree; new files inherit the private ACL. This uses one hidden, bounded system PowerShell invocation (four seconds, killed on cancellation), with literal paths passed outside the script. Permission failures stop access. Root/run/entry links and reparse points are rejected. Completed files are atomically published without overwriting an existing entry.

The default limits are 32 KiB trigger, 4 KiB preview, 8 MiB per entry, 16 MiB per run, 64 MiB total, 16 KiB per read page, and 24 hours retention. A host may provide stricter values through `SpillConfig`.

`SpillResultTransform` uses the trusted `RunContext.limits.max_tool_result_bytes` to choose the lower of the configured trigger and half of the Run result cap. It reserves both the serialized `ArtifactRef` and any existing structured metadata before creating the preview. A large plain-text body can be archived even when the tool also returns small structured metadata such as a shell exit code; that metadata, call identity and status are preserved exactly. Oversized structured values are not silently converted, truncated, or hidden in a text-only archive. If the cap cannot fit the reference and a clear retrieval marker, the original result follows normal Runtime limit handling. Restricted Run tool sets must contain the configured retrieval tool (`spill_read` standalone, `read` in the formal Server) before Spill publishes an artifact.

The formal Server now authorizes reads of an earlier Run's artifact within the same saved conversation: it checks current Run membership and the first acknowledged structured `ArtifactRef`, then reads from that original owner. User-supplied URI text and another conversation's references do not grant access. The backend's Run isolation remains unchanged. Expired/deleted data yields an explicit unavailable result, not an empty successful read; this is not permanent attachment storage. See [context management](../../docs/CONTEXT-MANAGEMENT.zh-CN.md).

`SpillStore::put_stream` is the single backend write path; `put(text)` forwards to it. It reserves the declared size under the storage lock, copies with a fixed buffer, verifies exact length and UTF-8, then syncs and publishes without overwriting. Unfinished temporary entries are owned by an RAII guard and removed on error or cancellation. It never loads a full command log into memory.

`SpillPlugin::archive()` returns the shared `SpillArchive` used by both its result transform and streaming tool adapters. Share this instance rather than constructing separate lifecycle trackers for the same store. It protects active Runs through publication and removes that protection in the awaited transform `finish`; direct hosts must call `finish` after their tools stop. The Server maps `tools::OutputArchive` to this interface, so output below and above the former Shell preview boundary has identical durability and authorization. Tools retain only an unindexed temporary capture while a command runs, not a second archive.

Validation: `cargo test -p spill` and `cargo test -p server --bin server spill_setup`. Browser restart integration uses `apps/web/test/context-e2e.mjs` with an isolated real host and tools.
